# Участие в разработке

Спасибо за интерес к Moon Core! У расширения нет зависимостей — ни рантаймовых, ни dev: `npm ci`
не нужен, хватает Node 22+.

## Быстрый цикл

```bash
git clone https://github.com/moonlivedt-oss/moon-core.git
cd moon-core
npm run build            # правил extension/runtime/src/ — собрать рантайм окна
npm test                 # всё, что гоняет CI: актуальность сборки, смоук, рантайм окна
npm run package          # dist/moon-core-<версия>.vsix
code --install-extension dist/moon-core-<версия>.vsix
```

Проверка без VS Code — стенд `node test/serve.js`: рантайм на макете интерфейса плюс настоящий
мост с фейковым хостом, `http://localhost:8792/test/fixture.html`.

Прогон в настоящем VS Code — `npm run e2e`: скачивает VS Code stable в `.vscode-test/` (около
гигабайта, один раз) и в его отдельной копии проходит внедрение, работу в окне и снятие. Твой
VS Code не трогается. Нужен, если меняешь внедрение в оболочку (`extension/lib/inject/`,
`extension/lib/wb-patch.js`).

## Как устроен код

Подробная карта файлов — в разделе «Как устроено» [README](README.md). Коротко:

- `extension/extension.js` — только активация и регистрация команд.
- `extension/lib/` — хост: мост, внедрение (`inject/`), сниппеты, конструктор, модули. Модули,
  помеченные в шапке «без vscode», гоняются тестами напрямую.
- `extension/runtime/src/` — **исходники** рантайма окна частями (`ui/` — конструктор и пипетка).
  Собранные `extension/runtime/mooncore-*.js` руками не правятся: `npm test` сверяет их с частями.
- `test/smoke/*.test.js` — тесты по темам; `test/runtime/` — поведение рантайма в заглушке DOM.

## Правила

- Страж структуры (`test/smoke/11-structure.test.js`): всё парсится, файл не длиннее 400 строк,
  переводы строк только LF. Разросся файл — дели на части.
- Стиль: осторожный, совместимый JS (рантайм исполняется в разных версиях воркбенча),
  оборонительные `try/catch` вокруг DOM и файловой системы, комментарии — на русском.
- Комментарий объясняет **почему**, а не пересказывает код.
- Без эмодзи: в коде, интерфейсе, Markdown и сообщениях коммитов.
- Всё, что приходит снаружи (окно, пакет вида, файл проекта, модуль), проверяется на входе.
  Новый метод моста — в `extension/lib/protocol.js`, с лимитами.
- Новая возможность — запись в `CHANGELOG.md` (раздел Unreleased) и проверка в тестах.
