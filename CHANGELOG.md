### Скорость VS Code и накладные расходы Moon Core (2026-10-06)

Двадцать улучшений после разбора кода, журнала с реальной машины, исходников VS Code 1.139/1.140 и
соседей по жанру. Главное — новая страница «Скорость VS Code»: Moon Core работает и в процессе
расширений, и в самом окне, поэтому видит то, чего не видит внешний лаунчер.

Скорость VS Code (`Moon Core: Скорость VS Code`, `lib/ext/speed.js`, модель — `lib/perf-model.js`,
`lib/perf-advice.js`, `lib/perf-scan.js`, вёрстка — `lib/speed-page.js`):

- **Активация каждого расширения в этом запуске**: загрузка кода и `activate()` по меткам, которые VS Code
  сам пишет в процессе расширений (`code/extHost/willActivateExtension/<id>` и др. в
  `globalThis.MonacoPerformanceMarks`). Без патчей и без сервисов окна; проверено в настоящем VS Code 1.140.
- **Когда расширение просится включаться** (`activationEvents`): «при старте (*)» и «после старта»
  выделены — их стоит выключать для папок, где они не нужны. Кнопка «Страница» открывает расширение.
- **Этапы старта окна**: конфигурация, загрузка кода, хранилище, папка и настройки, отрисовка,
  боковая панель, редакторы, нижняя панель, расширения — по меткам `code/willX`/`code/didX` окна,
  которые присылает рантайм (два раза: через 4 с после загрузки и полный набор через 25 с).
- **История запусков** (`mooncore-perf.json` в хранилище, общая для всех окон, до 60 запусков) и
  средняя стоимость каждого расширения по запускам.
- **Замедление запуска**: последний запуск в полтора раза и на секунду медленнее медианы (нужно от пяти
  прошлых) — Доктор пишет об этом, а окно в фокусе один раз в сутки предлагает «Что тормозит»
  (`moonCore.speedNotify`).
- **Подвисания окон**: Long Tasks API в окне считает задачи главного потока дольше 200 мс (с буфером
  старта), плюс память JS окна; приходит хосту с пульсом раз в минуту.
- **Тяжёлые папки проекта**: `node_modules`, виртуальные окружения, кэши сборщиков; `build`, `target`,
  `vendor`, `venv` — только с признаками (CMakeLists.txt, Cargo.toml, pyvenv.cfg...). Обход асинхронный
  и с бюджетом каталогов — на монорепозитории не подвесит процесс расширений.
- **Советы с «Применить» и «Вернуть как было»**, только по фактам и только для настроек, которые есть в
  этой версии VS Code: `files.watcherExclude` для найденных тяжёлых папок (в настройки папки),
  `search.followSymlinks` при `node_modules`, `editor.largeFileOptimizations`, если выключен,
  `workbench.editor.limit.enabled` при долгом восстановлении редакторов, `extensions.experimental.affinity`
  — медленные (в нескольких запусках) сторонние расширения в отдельный процесс. Прежнее значение
  запоминается (`mooncore.speed.applied`); объектные настройки пишутся только своей областью — VS Code
  сливает области сам (проверено по `mergeContents`).
- **Выгрузка для внешних программ**: поле `export` в `mooncore-perf.json` и команда «Сохранить замеры
  скорости в файл» — схема `moon-core/perf@1` (средняя, максимальная и последняя стоимость расширения,
  когда оно включается). Её может читать VS Code Launcher, чтобы выбирать стеки по замерам.
- **Сам Moon Core на странице**: своя активация (в e2e — 105–112 мс) и время рантайма в окне.
- **Доктор**: замедление запуска, дорогие расширения, подвисания — с кнопкой «Скорость VS Code»;
  кнопка есть и в полосе Доктора, меню статусбара, подсказке статусбара и панели «Вид».

Накладные расходы Moon Core:

- **Журнал больше не раздувается**: поиск модулей звали статусбар раз в 5 с, Доктор и проверка
  внедрения, и он каждый раз заново читал манифесты и писал ту же ошибку — на реальной машине журнал
  дорос до 673 КБ, 4991 из 5138 строк — «mlbg: такой id уже есть». Теперь поиск кэшируется по настройке,
  списку расширений и времени манифестов (`lib/module-discover.js`), ошибка пишется один раз за сеанс.
- **Повторы подряд в журнале** сводятся в одну строку «повторилась ещё N раз»; ротация файла считает
  байты, а не символы (кириллица в UTF-8 — два байта, файл рос до 2 МБ вместо 1).
- **Модуль найден дважды** (папка в `moonCore.modules` и установленное расширение с тем же id) — в
  Доктор понятной записью: какая копия работает, какая пропущена, кнопка «Открыть настройку».
- **Статусбар фоновых окон не опрашивается**: раз в 5 с пересчитывается только окно в фокусе; при
  получении фокуса — сразу.
- **Бандл воркбенча (около 20 МБ) не читается в каждом окне**: есть ли крючок сервисов и можно ли его
  поставить, запоминается в globalState по размеру и времени файла. Было: ~50 мс и ~40 МБ памяти
  на активацию каждого окна.
- **Таймеры рантайма спят в скрытом окне**: VS Code создаёт окна с `backgroundThrottling: false`
  (`out/main.js`), и в свёрнутом окне проверка кнопок (1,5 с), страховка стилей (10 с) и чтение адресов
  хостов (5 с) шли как в активном. Теперь кнопки и стили в скрытом окне не проверяются, адреса читаются
  раз в 15 с, а при показе окна всё догоняется сразу (`visibilitychange`).
- **Окно подключается к мосту быстрее**: пока ни один хост не на связи, адреса читаются с паузой
  300 мс -> 5 с вместо ровных 5 с. В e2e мост на связи через 2,2–3,2 с после старта окна вместо 5,1 с.

- Смоук 159, рантайм 48; e2e прошёл на VS Code 1.140.0 (два новых шага: активации расширений из меток и
  метки старта окна в истории). Прогон e2e поймал реальную ошибку: в VS Code 1.140 вложенных меток окна
  (чат, агенты) больше лимита, и поздние ключевые терялись — теперь шлются только этапы верхнего уровня.

- **Заводской бэкап оболочки**: если первый бэкап был снят с уже изменённого файла, он заменяется, как
  только оболочка без блока Moon Core снова равна заводской по исходному хэшу.

- **Доктор точнее про основу webview**: отдельно распознаётся случай, когда другая программа (Custom UI
  Style) отключила в ней защиту CSP, стерев `http-equiv` у meta-тега, — страницы при этом работают, и

### Файлы VS Code: webview, целостность, классы (2026-09-30)

По итогам разбора самой установки VS Code (`resources/app`): что в ней можно использовать и проверять.

- **Стили внутри webview** (`moonCore.webviewStyles`, команда «Стили внутри webview», по умолчанию выкл):
  CSS из сниппетов `webview*.css` дописывается в стили по умолчанию файла-основы webview
  (`out/vs/workbench/contrib/webview/browser/pre/index.html`) — так он доходит до страниц расширений и
  превью Markdown, куда CSS окна не попадает. Хэш инлайн-скрипта в CSP пересчитывается; правится только
  файл, у которого хэш сходился до нас; после правки — сверка; снятие возвращает файл байт в байт; CSS с
  обратной кавычкой, обратным слэшем и `${` не принимается (`lib/webview-patch.js`). Такие сниппеты в окно
  не идут; сохранил сниппет — основа обновляется сама. Хук удаления и аварийное восстановление снимают и это.
- **Целостность файлов VS Code** в Докторе (`lib/vs-files.js`): по каждому файлу из контрольных сумм
  `product.json` — исходный, изменён только Moon Core или изменён кем-то ещё; состояние основы webview;
  файлы других загрузчиков рядом с оболочкой (Custom UI Style, Custom CSS, cpp-docs-panel) с размером;
  предупреждение, если бэкап оболочки снят с уже изменённого файла. Только чтение.
- **«Точно сломано»** в проверке селекторов: класс из правила, которого нет ни в CSS, ни в коде воркбенча
  этой версии VS Code, значит переименование, а не «элемент не показан». Каталог Moon Core сверяется так же
  (в `npm test`, если рядом лежит VS Code из e2e).
- **Все значки VS Code** для своих кнопок: поиск по именам codicon, взятым из стилей окна (сотни вместо 30).
- **Любой цвет темы**: поиск по всем цветам темы VS Code во вкладке «Ещё» и правка найденного.
- **История правок переживает перезагрузку окна**: последние 15 шагов «Отменить» — в `mooncore-history.json`;
  снимки из файла проходят ту же проверку, что файл правок.
- **Восстановить сниппеты из копии**: наборы, отложенные перед перезаписью при загрузке вида.
- Тесты: `test/smoke/23-vs-files.test.js` (поддельная установка VS Code), e2e — `test/e2e/webview-steps.js`:
  настоящая webview открывается на правленой основе и видит CSS сниппета, после снятия файл равен
  исходному. Смоук 144, рантайм 45; e2e прошёл на VS Code 1.139.1.

### Ещё 12: инструменты конструктора, профили, переезд (2026-09-30)

- **Правило можно выключить, не удаляя** (вкладка «Правки», «Выключить» / «Включить»): операция
  `toggleRule`, флаг `off` у правила — едет в профилях и пакетах, отменяется через Ctrl+Z.
- **Правки «по состоянию»**: секция «Состояние» во вкладке «Элемент» — только под мышью (`:hover`),
  в фокусе (`:focus-within`) или пока нажат (`:active`). Страж корня окна видит корень и за состоянием.
- **Пипетка цвета** у каждого поля цвета: взять цвет с любого места экрана (`EyeDropper`).
- **Палитра**: недавние цвета и основные цвета текущей темы — одним щелчком.
- **Часть профиля**: «Взять только часть» в карточке профиля — элементы, настройки, цвета, эффекты
  или кнопки добавляются к текущему виду, профиль не переключается (`lib/engine-profiles.js`).
- **Переименование профиля** (операция `renameProfile`).
- **Следующий профиль** по кругу — команда `Moon Core: Следующий профиль вида`.
- **Вид через буфер обмена**: «Скопировать вид в буфер» / «Вставить вид из буфера» — правки и
  профили текстом; вставка проходит те же проверки и подтверждение, что загрузка из файла.
- **Галерея: предпросмотр** — стиль под курсором списка сразу виден в окне, до включения; три новых
  стиля («Вкладки по центру», «Вкладки без значков», «Спокойные заголовки секций»), всего 15.
- **Переезд с Custom CSS and JS Loader** (`lib/legacy-import.js`): локальные файлы из
  `vscode_custom_css.imports` становятся сниппетами; JS — только после одобрения.
- **Копии сниппетов перед перезаписью**: загрузка вида откладывает прежние версии одноимённых
  сниппетов в `backups/snippets-<время>` (пять последних наборов).
- **Уровни журнала** `moonCore.logLevel`: всё / только ошибки / выключен.
- Исправлено по дороге: галочка и переключатель больше не сливаются с предыдущим шагом истории
  (сливаются только «ползунки» — число, цвет, строка одного свойства).
- Тесты: `test/smoke/22-more.test.js`. Смоук 137, рантайм 45; e2e прошёл на VS Code 1.139.1.

### 30 улучшений: страховки, удобство конструктора, глубже в VS Code (2026-09-30)

Страховки и надёжность:
- **Безопасный режим** (`Moon Core: Безопасный режим`, Ctrl+Alt+Shift+F12): сниппеты, правки конструктора,
  эффекты и модули отключены во всех окнах, ничего не удаляется; значок в статусбаре и напоминание в
  окне (`lib/host-safety.js`, ключ `mooncore.safeMode`).
- **Стоп-кран в окне**: Ctrl+Alt+Shift+Backspace выключает и включает все стили Moon Core в этом окне
  без участия расширения (`runtime/src/86-panic.js`, `__MOONCORE__.panic()`).
- **Страж корня окна** (`lib/design-guard.js`): «скрыть», нулевая прозрачность, крошечный размер и
  открепление на `body`, `.monaco-workbench`, сетке частей, области редактора и интерфейсе Moon Core не
  принимаются — из окна, из файла правок, из профиля и из загруженного пакета.
- **Отменить / вернуть** (`lib/history.js`): до 40 шагов, правки одного свойства подряд — один шаг; отмена
  возвращает настройки VS Code и цвета темы. Вид, изменённый в другом окне, историю сбрасывает.
- **Резервные копии вида** (`lib/backups.js`): сами перед профилем, сбросом, загрузкой вида и
  восстановлением; 12 последних; команда «Восстановить вид из резервной копии».
- **Повреждённый файл правок** не затирается пустым видом: откладывается как `.corrupt`, вид — из копии.
- **Падающий JS-сниппет** (больше 8 ошибок за минуту) останавливается в окне до правки кода.
- **Проверка оболочки перед записью** (`wb-patch.shellProblem`): вне блока Moon Core и CSP ничего не
  меняется, блок один и в `<head>` — иначе запись не делается.
- **Пульс окон** (метод моста `hello`): хост знает живые окна и версию рантайма в каждом; Доктор и
  статусбар показывают окна со старым рантаймом.
- **Облегчённая рассылка состояния**: каталог и описания свойств (десятки КБ) уходят в файл состояния и
  приветствие потока, а не с каждой правкой.
- **Доктор**: «Починить всё», медленные модули (от 1,5 с), безопасный режим, окна, история и копии.
- **Загрузка чужого вида**: адреса, к которым стили пакета обращаются в сеть, перечислены в подтверждении.
- **Подсказки в CSS-сниппете**: после «Проверить элементы» селектор, который ничего не находит,
  подчёркнут в редакторе.

### VS Code для модулей (2026-09-29)

Модуль теперь видит, что происходит в VS Code, и добавляет в него своё настоящим API.
- События редактора своего окна: `mc.vscode.on("editor" | "cursor" | "save" | "diagnostics" |
  "debug" | "terminal" | "task" | "git" | "theme")`. Хост считает событие, только если на него
  подписаны (подписка подтверждается раз в минуту), и не шлёт повторов (`lib/host-vs.js`, `lib/vs-model.js`).
- Код под курсором через языковой сервер: `mc.vscode.symbol("word" | "hover" | "definition" | "symbols")`.
- Подсветка кода настоящим API (`createTextEditorDecorationType`): `mc.vscode.decorate/undecorate`,

  читает другое окно или антивирус), пауза через `Atomics.wait` вместо пустого цикла.
- Запись оболочки «всё или ничего»: упала запись посреди плана — уже записанное откатывается
  (оболочка не останется со ссылками на несуществующие файлы модулей).
- Статус оболочки кэшируется по времени изменения и размеру файлов: статусбар раз в 5 с больше
  не перечитывает workbench.html и product.json и не пересчитывает хэши.
- Опрос раз в 15 с пересобирает состояние, только если файлы сниппетов/конструктора изменились.
- Мост принимает RPC только с `Content-Type: application/json` (415 иначе).
- Журнал вырезает токены моста; последние 300 строк — в памяти для отчёта.
- Окно: самолечение стилей через `MutationObserver` на `<head>` (опрос 2 с -> 10 с страховкой),
  файл адресов хостов не разбирается повторно без изменений, таймер кнопок не ищет в DOM, когда
  кнопок нет, предупреждение при несовпадении версии протокола окна и расширения.

- «Скопировать отчёт»: диагностика, проблемы и хвост журнала в буфер обмена — без имени

### Конструктор мышкой
- **Ручки на рамке выбранного элемента**: правый край, низ и угол меняют ширину и высоту, кружок
  сверху справа — масштаб, квадрат снизу слева — внутренний отступ. Во время перетаскивания рядом
  видно значение, двойной клик по ручке возвращает как было.
- **Порядок мышкой**: элемент в ряду с соседями (пункты статусбара, иконки панели активности,
  кнопки) перетаскивается за «::» над рамкой; вставка показана линией. Во вкладке «Элемент» —
  секция «Порядок» (раньше / позже / как было), на «Карте» строки поштучных списков тоже
  перетаскиваются. Работает через CSS `order`, учитывает обратный порядок правой части статусбара.
- **«Как было»** в нижней полосе конструктора: пока кнопка нажата, окно показано без правок CSS
  (конструктор и CSS-сниппеты). Настройки VS Code при этом не переключаются.
- **Подсветка из «Правок»**: навёл на правку — её элементы обведены в окне; скрытые этой правкой
  на время показываются. На «Карте» наведение подсвечивает элемент или пункт списка.
- **Элементы не из каталога**: для выбранного элемента предлагаются другие однозначные селекторы
  (id, aria-label, title, якорь по предку с id, `:has` по подписи потомка).

### Самолечение правок
- У каждой правки конструктора запоминается **отпечаток элемента**: запасные селекторы, id,
  aria-label, title, роль, текст, классы, запись каталога. Правкам, созданным раньше, отпечаток
  дописывается сам, когда их элемент на экране.
- Правило перестало что-либо находить (VS Code переименовал классы) — проверка селекторов ищет
  элемент по отпечатку и предлагает замену: «Починить (N)» после обновления VS Code, в «Проверить
  селекторы» и в «Докторе». Принятая замена переносит правило на новый селектор и во всех своих
  профилях. Найденные «по признакам» по умолчанию не отмечены — там решает человек.

### Профили
- **Профиль по теме и времени суток**: условия `themes` (dark, light, highContrast,
  highContrastLight) и `time` («22:00-07:00», можно через полночь) в `moonCore.autoProfiles`.
- **Профиль проекта** `.vscode/mooncore.json`: вид едет вместе с репозиторием — либо
  `{ "use": "Минимал" }`, либо свои правила и настройки. Включается только после согласия (один
  раз на содержимое файла; изменился — спросит снова), проходит те же проверки, что профиль, части
  модулей из проекта не берутся. Важнее правил `autoProfiles`. Команда `Moon Core: Сохранить вид в
  проект` пишет текущие правки в этот файл.

### Модули: разработка
- **Режим разработки модуля** (`Moon Core: Режим разработки модуля`, на сеанс): сохранил код
  модуля — он сразу перезапускается в открытых окнах без внедрения и перезагрузки. Перед
  перезапуском модуль убирает за собой (`mc.onDispose`), новый код отдаёт хост (метод моста
  `moduleCode`, только модулю в этом режиме). Блок в оболочке обновляется молча для следующего запуска.
- **`Moon Core: Создать модуль`**: папка с манифестом, заготовкой `runtime.js`, `assets/`,
  типами и `jsconfig.json`; папка сразу добавляется в `moonCore.modules`.
- **Типы** `types/mooncore.d.ts`: помощник модуля в окне, `window.__MOONCORE__`, API расширения
  (`apiVersion: 1`), манифест. В помощнике модуля новые `onDispose(fn)` и `hot`.

### Доктор
- `Moon Core: Доктор` — одна страница со всем состоянием: оболочки (внедрено, актуальность, хэш,

- `lib/host.js` разделён: `host-snippets.js`, `host-transfer.js`, `host-context.js`,
  `host-check.js` подмешиваются в класс хоста.
- **Прогон в настоящем VS Code**: `npm run e2e` скачивает VS Code stable в `.vscode-test/` (проверка

  `product.json` вернулись к исходным). Твой VS Code не трогается.
- Тестов: смоук 51, рантайм 17.

### Безопасность
- **Хэш оболочки не «узаконивает» чужие правки**: `product.json` правится, только если без блока
  Moon Core оболочка совпадает с оригиналом, или если чужие вставки (например, CPPDOCS-WINDOW)
  ты одобрил. Изменились — Moon Core спросит снова; без одобрения баннер «повреждена» остаётся.
- **Запись с правами администратора без подмены**: скрипт идёт в `-EncodedCommand`, в нём
  SHA-256 каждого файла; повышенный процесс сначала сверяет все хэши, потом пишет ровно
  проверенные байты. Итог сверяется ещё раз после записи.
- **Код модулей — только одобренный**: изменился скрипт модуля на диске — в оболочку идёт прежняя
  одобренная копия (`globalStorage/modules-approved`), новая — после «Встроить» или «Всегда
  доверять этой папке».
- **JS-сниппеты — только одобренные**: сохранённые в редакторе VS Code, созданные командой или
  загруженные с подтверждением. Изменённые снаружи (другая программа, тихое восстановление из
  синхронизации) не запускаются, пока не одобришь. В подтверждении загрузки пакета перечислены JS.
- **Настройки, дающие выполнить код, не синхронизируются** (`scope: machine`): разрешённые команды,
  пути модулей, режимы внедрения.
- **Проверка целостности файлов модулей** (`integrity`, `moonCore.moduleIntegrity`): подменённый
  файл не выполнится. Если сборка VS Code проверку не поддерживает, рантайм сообщает, и она
  выключается для этой версии (файлы переписываются).
- **Мост только на портах 47300–47319**, и в CSP оболочки разрешены ровно они (было «любой порт
  127.0.0.1»). Лимит 600 запросов за 10 с, до 64 потоков событий, файл адресов — только владельцу.
- **Правка блока Moon Core снаружи** замечается: предупреждение и перезапись блока.
- **Журнал без имени пользователя**: домашняя папка заменяется на `~`.

### Внедрение
- **Нет баннера «установка повреждена»** (`moonCore.fixChecksum`, по умолчанию вкл): после записи
  оболочки Moon Core пересчитывает её хэш в `product.json`. Исходный `product.json` один раз
  кладётся рядом как `.mooncore-backup`, при снятии возвращается ровно исходная запись. Если
  оболочку потом переписал другой загрузчик, хэш тихо чинится при следующем запуске.
- **Встраивать заново после обновления VS Code без вопроса** (`moonCore.autoReinject`, по умолчанию
  выкл; в вопросе после обновления есть кнопка «Всегда внедрять сам»).
- **Модули — отдельными файлами рядом с оболочкой** (`moonCore.moduleFiles`, по умолчанию вкл):
  `mooncore-mod-<id>.js` подключается обычным `<script src>`. Оболочка у MoonLight BG похудела с
  ~600 до ~30 КБ. Лишние файлы модулей убираются при каждом внедрении и при снятии.
- **Защита запуска**: рантайм помечает, на каком модуле идёт загрузка. Если прошлый запуск на нём
  не завершился, модуль один раз пропускается (первая строка файла модуля) с уведомлением;
  три незавершённых запуска без виновника — пропускаются все модули.
- **Аварийное восстановление**: `moon-core-restore.cmd` (`.sh`) в папке данных расширения
  снимает блок самим Code.exe в режиме Node, даже когда VS Code не открывается. Путь — в диагностике.
- **Запись с правами администратора**: если VS Code стоит в Program Files, внедрение и снятие
  предлагают одну запись через UAC вместо ошибки «нет прав».
- **Время запуска в диагностике**: рантайм и каждый модуль в мс (метод моста `timing`).
- **Окно агентских сессий** (`moonCore.injectSessions`, по умолчанию выкл): внедрение и в `sessions.html`.
- **Следы старого загрузчика**: пустые метки Custom CSS and JS в оболочке — предложение убрать
  (один раз на версию VS Code). Непустые блоки живых загрузчиков не трогаются.

### Конструктор и профили
- Конструктор интерфейса: клик по любому элементу открывает панель свойств (скрыть, прозрачность, фон, скругление, масштаб, отступ, шрифт, жирность, цвет, ширина и высота).
- Каталог элементов VS Code (31 запись) со связанными настройками: где есть штатная настройка, конструктор предлагает её первой.
- Карта интерфейса: все зоны окна VS Code списком, видимость элементов галочками; пункты статусбара и иконки панели активности — поштучно.
- Вкладка «Правки»: список всех правок с отменой по одной и общим сбросом; для настроек запоминается и возвращается исходное значение.
- Однотипные элементы меняются по одному, «Все такие» — отдельной кнопкой. Панель конструктора уходит на другую сторону, если закрывает элемент, и перетаскивается за заголовок.
- «Скрыть» в пипетке пишет в конструктор (с отменой), а не в hidden.css.
- Профили вида: встроенные «Минимал», «Только код», «Крупный», свои (сохранить, обновить, удалить), «Исходный вид VS Code». Применение откатывает настройки к исходным значениям VS Code, флаг «изменён» после правок. Команда `Moon Core: Профили вида`.
- **Профили по контексту** (`moonCore.autoProfiles`, `moonCore.autoProfileDefault`): профиль включается сам по языку активного файла, папке проекта или git-ветке (звёздочки в папках и ветках). Решает окно в фокусе; несохранённые правки конструктора не затираются.
- **Профиль несёт состояние модулей**: при сохранении профиля модули отдают свой снимок (`mc.profile({ save, apply })`), при применении получают его обратно (событие моста `profile`). Один профиль переключает и раскладку интерфейса, и, например, фон MoonLight BG. На карточке профиля видно, каких модулей он касается.

### Модули
- Moon Core впечатывает рантаймы других плагинов своим блоком (инлайн, с nonce), сразу после собственного рантайма. Объявление в package.json расширения (`moonCore.modules`) или папкой с `mooncore-module.json` (настройка `moonCore.modules`; папка важнее расширения с тем же id).
- Согласие на каждый новый модуль, привязанное к id и источнику; команда `Moon Core: Модули`.
- Помощник модуля в окне `__MOONCORE__.module(id)`: `base`, `on`, `get`, `rpc`, `log`, `connected`, `data`, `saveData`, `profile`. API для расширений: `activate()` возвращает `{ apiVersion: 1, module(id) }` с `publish`, `onRequest`, `readData`, `writeData`.
- События с `scope: "window"` доходят только до окна своего хоста.
- Файл данных модуля (`modules/<id>.json`, до 1 МБ): окно читает его синхронно при старте, пишет через мост (метод `moduleData`).
- Блок в оболочке обновляется сам, когда меняется состав модулей или их рантайм. Проверки: путь только внутри папки модуля, лимиты 4 МБ / 12 МБ / 16 модулей, 256 КБ на событие.

### Надёжность
- **Проверка после обновления VS Code**: один раз на версию Moon Core сам проверяет селекторы сниппетов, правок конструктора и каталога и предупреждает, если правила перестали что-либо находить (переименованные классы). «Проверить селекторы» теперь тоже охватывает конструктор и каталог.
- **Своё окно находится надёжнее**: кроме события `focus` от хоста окно, получив фокус, само опрашивает хосты (метод `focus`) — это закрывает гонки при быстром переключении окон.
- Если блок Moon Core пропал из оболочки без обновления VS Code (её перезаписал другой загрузчик), при запуске предлагается внедрить снова.

### Перенос между машинами
- `Moon Core: Экспорт вида в файл` / `Импорт вида из файла`: правки конструктора, профили (с частями модулей) и сниппеты одним JSON. Импорт показывает, что заменится и какие сниппеты перезапишутся; всё входящее проходит те же проверки, что и правки из окна.
- Синхронизация через Settings Sync (`moonCore.sync`): копия вида в настройке `moonCore.syncData` (до 512 КБ; сниппеты не влезают — едут только конструктор и профили). На пустой машине вид восстанавливается сам, иначе Moon Core спрашивает. `Moon Core: Загрузить вид из синхронизации` — вручную.

### Безопасность
- Команды VS Code из JS-сниппетов (`mc.command`): каждая новая команда — только после согласия («Разрешить всегда» запоминается, «Запретить» — до конца сессии); заранее разрешённые — `moonCore.allowedCommands`. В запросе теперь указан сниппет-источник.

### Разработка
- Движок конструктора вынесен в lib/engine.js (без vscode). Новые чистые модули с тестами: lib/checks.js, lib/commands.js, lib/bundle.js, lib/autoprofile.js.
- Поведенческие тесты рантайма (test/runtime.js, заглушка DOM, поддельные EventSource и fetch, два хоста): сниппеты, конструктор, проверка селекторов, модули, пара окно-хост, профили. `npm test` = смоук (37) + рантайм (9).
- Стенд поднимает настоящий мост с фейковым хостом, демо-модуль, `/test/publish`, подключает настоящий модуль: `node test/serve.js --module ../vscode-bg`.
