## Быстрый старт

```bash
npm run package                                   # собрать dist/moon-core-<версия>.vsix
code --install-extension dist/moon-core-0.1.0.vsix
```

Перезапусти VS Code и согласись внедрить Moon Core в оболочку (или команда
`Moon Core: Внедрить в VS Code`), затем перезагрузи окно. Конструктор — кнопка на панели Moon Core
или `Moon Core: Конструктор интерфейса`.

> Расширение раздаётся собственным `.vsix`, в маркетплейсе его нет: оно правит файлы самого
> VS Code, а такое Marketplace не пропускает. Подробности и риски — в [SECURITY.md](SECURITY.md).

## Что это

Платформа кастомизации и внедрения в интерфейс VS Code. Расширение (хост) плюс рантайм,
впечатанный прямо в оболочку редактора (`workbench.html`). Поэтому Moon Core умеет то, чего
нет в API расширений: менять и дополнять любой элемент интерфейса. При этом он не теряет
доступа к API: команды, файлы и редактор остаются под рукой.

Локальное расширение (`.vsix`), не для Marketplace. Ноль зависимостей.

## Конструктор

Главное в Moon Core. Команда `Moon Core: Конструктор интерфейса` (или кнопка на панели Moon Core,
или меню по клику на «Moon» в статусбаре) превращает окно VS Code в редактируемый макет:

- навёл — элемент подсвечен и подписан («Миникарта», «Вкладка», «Пункт статусбара»);
- кликнул — открывается панель свойств этого элемента;
- Alt+клик — обычный клик (открыть меню, переключить вкладку), не выходя из конструктора.

Что можно сделать с элементом:

| Раздел | Что внутри |
|---|---|
| **Настройки VS Code** | Если для элемента есть штатная настройка (миникарта, хлебные крошки, вкладки, панель активности, центр команд, размер шрифта кода, терминал...), она показана первой. Это надёжный способ: переживает обновления. |
| **Вид** | Скрыть, прозрачность, фон, скругление |
| **Размер** | Масштаб (`zoom`), внутренний отступ; отдельно ширина и высота |
| **Текст** | Размер шрифта, жирность, шрифт, цвет |

Правка видна сразу, сохраняется сама и попадает во вкладку **«Правки»**. Там весь список
того, что ты поменял, и у каждого пункта есть крестик «вернуть как было». Для настроек VS Code
запоминается исходное значение, и при отмене возвращается именно оно. Скрытые элементы
возвращаются тоже отсюда.

### Прямо на элементе

У выбранного элемента на рамке есть ручки: тяни мышкой, значение видно рядом.

| Ручка | Что меняет |
|---|---|
| правый край, низ, угол | ширину и высоту |
| кружок сверху справа | масштаб |
| квадрат снизу слева | внутренний отступ |
| «::» сверху слева | место среди соседей (перетащи; вставка показана линией) |

Двойной клик по ручке возвращает как было. Порядок работает для элементов в ряду: пункты
статусбара, иконки панели активности, кнопки. Во вкладке «Элемент» для них есть секция «Порядок»
(раньше, позже, как было), а на «Карте» строки поштучных списков тоже перетаскиваются.

**«Как было»** в нижней полосе конструктора: пока кнопка нажата, окно показано без правок CSS
(до / после). Настройки VS Code при этом не переключаются.

Во вкладке «Правки» наведение на правку обводит её элементы в окне, а скрытые этой правкой
элементы на это время показываются. На «Карте» наведение подсвечивает элемент.

### Цвета темы

Выбрал элемент — секция «Цвета темы» показывает, какой цвет темы его красит (например
`statusBar.background`), и меняет его через штатную настройку `workbench.colorCustomizations`.
Это надёжнее CSS: переживает обновления и меняет цвет везде, где тема его использует. Для текста
кода (элемент «Текст кода») есть «Цвета кода»: комментарии, строки, ключевые слова, числа, типы,
функции, переменные. Всё отменяется во вкладке «Правки», прежние значения возвращаются.

### Когда применять

Любую правку можно ограничить: только в языке (markdown), только на ветке, только в проекте,
только в светлой или тёмной теме — секция «Когда применять». Например: миникарта спрятана только
в markdown, красный статусбар только на ветке main. Это работает и в CSS-сниппетах:
`html[data-mc-lang="markdown"] .minimap { display: none; }`.

### Вкладка «Ещё»

- **Свои кнопки**: любая команда VS Code — кнопкой в статусбаре, титлбаре или над редактором.
  Команду выбираешь в списке VS Code, дальше значок, подпись и место.
- **Эффекты редактора**: след за курсором, искры при наборе, свечение строки и курсора; рядом
  плавный курсор, его форма и мигание, плавная прокрутка, лигатуры.
- **Отдельные окна**: редактор или группу — в отдельное окно VS Code (например, на второй монитор).

Любой элемент можно ещё и **открепить** прямо в этом окне: «Элемент» → «Плавающее окно».

### Глубокая интеграция

Команда `Moon Core: Глубокая интеграция`, обе части по умолчанию выключены:

| Часть | Что даёт | Что правится |
|---|---|---|
| **Сервисы окна** | Moon Core и модули получают настоящие сервисы окна VS Code: `mc.service("statusbarService")`, `codeEditorService`, `commandService`... | одна строка в `workbench.desktop.main.js` (бэкап рядом, хэш в `product.json` пересчитывается) |
| **Главный процесс** | `Moon Core: Вид окна`: непрозрачность окна, «поверх всех окон», акрил или слюда Windows 11, vibrancy macOS | импорт в `out/main.js` (в контрольные суммы не входит) и `mooncore-main.mjs` |

После включения нужен полный перезапуск VS Code (закрыть все окна). Сервисы окна — внутренний
API VS Code: он меняется между версиями, поэтому `mc.service` может вернуть `null`, а форма
объекта — отличаться. Материал Windows 11 виден там, где интерфейс прозрачный (например, с
MoonLight BG). «Убрать из VS Code», хук удаления и `moon-core-restore.cmd` снимают и эти патчи.

### Самолечение после обновлений VS Code

К каждой правке Moon Core запоминает отпечаток элемента: запасные селекторы (id, aria-label,
title), текст, классы, запись каталога. Если VS Code переименовал классы и правка перестала
что-либо находить, проверка селекторов ищет элемент по отпечатку и предлагает замену: кнопка
«Починить» после обновления VS Code, в «Проверить селекторы» и в «Докторе». Принятая замена
переносит правило на новый селектор и во всех своих профилях.

### Карта интерфейса

Вкладка **«Карта»** открывается первой: всё, что есть в окне VS Code, по зонам (окно, титлбар,
панель активности, боковая панель, редактор, нижняя панель, статусбар).

- галочка показывает или скрывает элемент: миникарту, хлебные крошки, центр команд, кнопки раскладки, полосу вкладок и т.д.;
- пункты статусбара и иконки панели активности перечислены **поштучно**, ненужные снимаются галочкой;
- «Настроить» открывает все свойства элемента, даже если его сейчас нет на экране (например, «Масштаб окна»).

Где возможно, галочка переключает настройку VS Code, иначе ставит правило «скрыть». Если
включить элемент обратно, вернётся то значение, что было до тебя.

### Профили вида

Вкладка **«Профили»** (или команда `Moon Core: Профили вида`, быстрый выбор списком):

- **встроенные:** «Минимал» (без второстепенных кнопок и панелей), «Только код» (ещё и без панели активности, статусбара и полей), «Крупный» (масштаб и шрифты больше);
- **свои:** настроил вид и нажал «Сохранить» под своим именем;
- **«Исходный вид VS Code»** снимает все правки.

Применение профиля заменяет текущие правки (перед этим спрашивается подтверждение). Настройки
всегда откатываются к исходным значениям VS Code, а не к прошлому профилю, поэтому «Исходный вид»
после любых переключений возвращает VS Code ровно к тому, каким он был. Если после применения
профиля что-то поменял, это видно («изменён»), и профиль можно «Обновить».

### Профили по контексту

Профиль может включаться сам — по языку открытого файла, папке проекта, git-ветке, виду
темы или времени суток. Правила — в `settings.json`, первое подходящее выигрывает:

```jsonc
"moonCore.autoProfiles": [
  { "profile": "Только код", "languages": ["markdown"] },
  { "profile": "Минимал", "folders": ["work-*"], "branches": ["release/*"] },
  { "profile": "Ночь", "time": "22:00-07:00" },          // можно через полночь, можно списком
  { "profile": "Светлый", "themes": ["light"] }           // dark, light, highContrast, highContrastLight
],
"moonCore.autoProfileDefault": ""   // профиль, когда ничего не подошло (пусто — не менять)
```

Внутри правила все условия должны совпасть, внутри списка — любое; в папках и ветках работает
`*`. Профиль и настройки VS Code общие для всех окон, поэтому решает окно в фокусе. Если в
конструкторе есть несохранённые правки, профиль не переключится (сообщение в статусбаре): сохрани
их в профиль, и авто-переключение продолжит работать.

### Профиль проекта

Вид может ехать вместе с репозиторием: файл `.vscode/mooncore.json` в папке проекта.

```jsonc
{ "mooncore": 1, "note": "Для ревью", "use": "Минимал" }                 // включить готовый профиль
{ "mooncore": 1, "note": "...", "rules": { ... }, "settings": { ... } }   // или свой вид
```

При первой встрече с файлом Moon Core спросит, включать ли его (изменился файл — спросит
снова). Свой вид проекта хранится как профиль «Проект <папка>». Файл проходит те же проверки,
что и профиль, а части модулей из проекта не берутся. Профиль проекта важнее правил
`autoProfiles`. Команда `Moon Core: Сохранить вид в проект` пишет текущие правки в этот файл.

### Профиль и модули

Профиль хранит не только правки интерфейса, но и состояние модулей, которые это умеют. Например,
MoonLight BG кладёт в профиль свой образ фона: «Только код» может заодно включать спокойный
фон, а профиль по ветке — свой набор. На карточке профиля это видно («+ MoonLight BG»).

### Мелочи

Однотипные элементы (вкладки, пункты статусбара, иконки) по умолчанию меняются по одному.
Кнопка «Все такие» применяет правку ко всем элементам этого типа. «Родитель» поднимается на
уровень выше, если кликнул в мелкую деталь.

Сбросить всё: кнопка «Сбросить всё» во вкладке «Правки» или команда
`Moon Core: Сбросить изменения конструктора`.

## Что ещё умеет

| Возможность | Как |
|---|---|
| **CSS-сниппеты** | Обычные `.css`-файлы, правятся в редакторе VS Code. Правки видны **сразу, на каждый символ** (живой предпросмотр), а после сохранения остаются насовсем. |
| **JS-сниппеты** | Выполняются в окне VS Code с помощником `mc`. Всё, что создано через него, при правке или выключении убирается само. |
| **Конструктор** | См. выше: клик по элементу, панель свойств, список изменений с отменой. |
| **Пипетка** | `Ctrl+Alt+Shift+C`: подсветка элемента под курсором, колесо переходит к родителю или потомку, клик открывает меню: «Стиль в CSS», «Скрыть», «Копировать селектор». Селектор можно поправить прямо в меню, счётчик совпадений обновляется на лету. |
| **Проверка селекторов** | Показывает, какие правила сниппетов и правки конструктора перестали находить элементы. После обновления VS Code запускается сама, один раз на версию, и предлагает починить правки по отпечаткам. |
| **Доктор** | `Moon Core: Доктор`: всё состояние на одной странице (оболочка, хэш, мост, окна, время запуска, модули, правки, сниппеты) и список «Что не так» с кнопкой починки у каждого пункта. |
| **Перенос вида** | «Экспорт вида в файл» / «Импорт вида из файла»: конструктор, профили и сниппеты одним JSON. С `moonCore.sync` вид едет через Settings Sync и на новой машине восстанавливается сам. |
| **Самовосстановление** | Если VS Code перестроил DOM, стили возвращаются. Если VS Code обновился и оболочка пересоздана, при запуске появится предложение внедрить заново. Новая версия рантайма обновляется в оболочке автоматически. |
| **Команды из интерфейса** | `mc.command('workbench.action.terminal.toggleTerminal')`: кнопка, встроенная в интерфейс, вызывает команду VS Code. Каждую новую команду Moon Core сначала спросит. |

## Установка

```bash
npm test
npm run package
code --install-extension dist/moon-core-0.1.0.vsix
```

При первом запуске расширение спросит, внедрять ли рантайм в оболочку. Команда та же:
`Moon Core: Внедрить в VS Code`. После перезагрузки окна VS Code может написать, что установка
«повреждена» — Moon Core сам пересчитывает хэш оболочки в `product.json` (`moonCore.fixChecksum`),
поэтому баннера нет. Раньше это было ожидаемо для любого патча оболочки (так же работают custom-css и
cpp-docs-panel), и на работу редактора не влияет.

Снять: `Moon Core: Убрать из VS Code`. При удалении расширения блок снимается сам (хук `vscode:uninstall`).


### Надёжность внедрения

| Что | Как |
|---|---|
| **Нет баннера «повреждена»** | Хэш оболочки в `product.json` пересчитывается при записи и возвращается при снятии (`moonCore.fixChecksum`). |
| **После обновления VS Code** | Moon Core спросит, встроить ли заново; кнопка «Всегда внедрять сам» включает `moonCore.autoReinject` — дальше без вопросов. |
| **Модули файлами** | `mooncore-mod-<id>.js` рядом с оболочкой вместо инлайна (`moonCore.moduleFiles`): оболочка лёгкая, скрипт кэшируется. |
| **Защита запуска** | Если окно не запустилось на модуле, в следующий раз он пропускается (с уведомлением); после перезагрузки — снова пробуется. |
| **Если VS Code не открывается** | Закрой VS Code и запусти `moon-core-restore.cmd` из папки данных расширения (`%APPDATA%\Code\User\globalStorage\moonlivedt.moon-core\`): блок снимется, хэш вернётся. Путь есть в диагностике. |
| **VS Code в Program Files** | Вместо ошибки «нет прав» — одна запись с правами администратора (UAC). |
| **Время запуска** | `Moon Core: Диагностика` показывает, сколько миллисекунд стартовали рантайм и каждый модуль. |
| **Окно сессий** | `moonCore.injectSessions` — встраивать и в окно агентских сессий (VS Code 1.121+). |
| **Несколько окон сразу** | Оболочку пишет одно окно за раз (блокировка `mooncore-inject.lock` в папке данных): после обновления VS Code окна не перемешивают записи, остальные дожидаются первого и видят, что всё уже сделано. |
| **Лёгкий старт окна** | В оболочку встраивается только ядро (~90 КБ из 180): конструктор и пипетка лежат файлом в папке данных и грузятся при первом открытии (`moonCore.lazyUi`). Файл сверяется по SHA-256, для Trusted Types VS Code в CSP добавляется политика `mooncore`. Если какой-то VS Code так загрузить не даст, Moon Core сам встроит интерфейс целиком. |


### Безопасность

Moon Core исполняет код в окне VS Code, поэтому ничего не встраивается и не запускается молча:

- **модули** — каждый новый спрашивает разрешения, а изменённый код модуля встраивается только
  после «Встроить» (для своей папки разработки — «Всегда доверять этой папке»);
- **JS-сниппеты** — запускается только код, который ты видел: сохранённый в VS Code, созданный
  командой или загруженный с подтверждением;
- **оболочка** — хэш в `product.json` пересчитывается, только если в ней нет чужих вставок или
  ты их одобрил: баннер «повреждена» не прячет чужое вмешательство;
- **права администратора** — данные сверяются по SHA-256 внутри повышенного процесса, подменить
  их во временной папке нельзя;
- **мост** — только 127.0.0.1, порты 47300–47319, токен на каждый запуск, проверка Origin и Host,
  лимит частоты; в CSP разрешены только эти порты;
- настройки, дающие выполнить код, в Settings Sync не попадают; в журнале нет имени пользователя.

## Сниппеты

Панель **Moon Core** на боковой панели активности:

- галочка включает или выключает сниппет;
- клик открывает сниппет в редакторе;
- кнопки сверху: пипетка, новый CSS, новый JS, проверка селекторов;
- в меню `...` есть папка сниппетов, диагностика, внедрение и снятие.

Файлы лежат в `globalStorage` расширения (`snippets/*.css`, `snippets/*.js`). Порядок
применения CSS совпадает с порядком имён, так что каскад предсказуем (`00-base.css`, `10-tabs.css`, ...).
Пипетка складывает скрытые элементы в `hidden.css`, а заготовки стилей — в активный
CSS-сниппет или в `picked.css`.

### Помощник `mc` в JS-сниппетах

```js
mc.watch(selector, el => { ... })   // для каждого элемента по селектору, в том числе будущих
mc.el(tag, props, children)         // создать элемент
mc.mount(parent, node)              // вставить (уберётся при выгрузке)
mc.css(text)                        // добавить стиль
mc.on(target, event, fn)            // подписка
mc.every(ms, fn) / mc.after(ms, fn) // таймеры
mc.command(id, ...args)             // команда VS Code, Promise
mc.toast(text)                      // короткое сообщение
mc.onDispose(fn)                    // своя уборка
mc.$(sel) / mc.$$(sel)              // поиск элементов
```

Пример: кнопка в статусбаре, которая открывает терминал.

```js
mc.watch('.statusbar .right-items', (bar) => {
    const btn = mc.el('div', { className: 'statusbar-item', textContent: 'TERM', title: 'Терминал' });
    btn.style.cursor = 'pointer';
    mc.on(btn, 'click', () => mc.command('workbench.action.terminal.toggleTerminal'));
    mc.mount(bar, btn);
});
```

Ошибки сниппетов попадают в журнал (`Moon Core: Показать журнал`) и показываются уведомлением
с кнопкой «Открыть».

## Модули

Модуль — рантайм другого плагина, который Moon Core впечатывает в оболочку VS Code своим
блоком, сразу после собственного рантайма. Модулю не нужен ни свой патч `workbench.html`, ни
be5invis / custom-ui-style: внедрение, nonce в CSP, обновление после апдейта VS Code и снятие
при удалении делает ядро.

### Как объявить модуль

Из расширения: в его `package.json`

```json
"moonCore": {
  "modules": [
    { "id": "mlbg", "name": "MoonLight BG", "version": "20.0.0", "script": "custom-bg.js", "assets": "." }
  ]
}
```

Из папки (удобно при разработке): положить в папку `mooncore-module.json` с тем же объектом
и добавить путь к папке в настройку `moonCore.modules`.

| Поле | Что это |
|---|---|
| `id` | `^[a-z][a-z0-9-]{1,31}$`, уникальный |
| `script` | рантайм модуля, путь внутри папки модуля (наружу через `..` и симлинки нельзя), до 4 МБ |
| `assets` | папка ресурсов внутри модуля (по умолчанию корень), окно получит её адрес |
| `name`, `version` | для людей и диагностики |

Каждый новый модуль встраивается только после согласия: Moon Core спросит один раз.
Разрешение привязано к id и источнику: тот же id из другого места спросит заново.
Команда `Moon Core: Модули` включает и выключает модули списком. Пересобрал рантайм модуля,
и Moon Core сам обновит блок и предложит перезагрузить окно.

### Свой модуль: заготовка и режим разработки

`Moon Core: Создать модуль` делает папку с манифестом, заготовкой `runtime.js`, папкой
`assets`, типами `mooncore.d.ts` и `jsconfig.json` (подсказки в VS Code) и добавляет её в
`moonCore.modules`. Дальше — `Moon Core: Модули`, чтобы разрешить.

`Moon Core: Режим разработки модуля` (до перезапуска VS Code): сохранил код модуля — он сразу
перезапускается в открытых окнах, без вопроса и без перезагрузки. Перед перезапуском модуль
должен убрать за собой всё, что создал: `mc.onDispose(fn)`; номер перезапуска — `mc.hot`.
Типы всего API — в `extension/types/mooncore.d.ts`.

### В окне: помощник модуля

```js
var mc = window.__MOONCORE__ && window.__MOONCORE__.module("mlbg");
if (mc) {
    mc.base;                                   // адрес папки ресурсов, со слэшем на конце
    var off = mc.on("live", function (d) {});  // событие от своего расширения (последнее значение придёт сразу)
    mc.get("live");                            // последнее значение или undefined
    mc.rpc("save", { a: 1 }).then(function (r) { /* {ok, result} или {ok:false, error} */ });
    mc.log("где", err);                        // в журнал Moon Core
    mc.profile({ save: () => ({}), apply: (obj, name) => {} });   // своя часть в профилях вида
    mc.data();                                 // файл данных модуля: синхронно при старте (объект или null)
    mc.saveData({ cfg: {} });                  // сохранить файл данных (через мост, пишет хост)
    mc.onDispose(function () {});              // уборка перед горячей перезагрузкой (режим разработки)
    mc.hot;                                    // сколько раз модуль перезапущен (0 — обычный запуск)
    mc.connected();                            // есть ли связь с расширением

    // Настоящий API VS Code через хост своего окна:
    mc.vscode.statusItem("sync", { text: "$(sync) 3", tooltip: "..." });   // элемент статусбара VS Code
    mc.on("nativeClick", function (d) { /* d.item === "sync" */ });
    mc.vscode.notify("Готово", { buttons: ["Открыть"] }).then(function (r) { /* r.result */ });
    mc.vscode.quickPick(["a", "b"]); mc.vscode.input("Имя?"); mc.vscode.open("C:/x.txt");
    mc.vscode.config("editor.fontSize"); mc.vscode.context();              // язык, ветка, проект, тема
}
```

Расширению, которому нужна только кнопка, свой модуль не нужен:

```js
const core = await vscode.extensions.getExtension("moonlivedt.moon-core").activate();
const b = core.ui("Моё расширение").button({ id: "run", zone: "titlebar", icon: "rocket", tooltip: "Запуск", command: "my.run" });
b.dispose();                                       // убрать
```

Модуль, которого нет в списке разрешённых, помощника не получит (`module()` вернёт `null`).
Хорошо, если модуль умеет жить и без Moon Core: так проще переезжать.

### В расширении: API Moon Core

```js
const ext = vscode.extensions.getExtension("moonlivedt.moon-core");
const core = ext && await ext.activate();          // { apiVersion: 1, module(id) }
const mod = core.module("mlbg");
mod.publish("live", { branch: "main" }, { scope: "window" });   // только окну этого хоста
mod.publish("theme", "dark");                                   // всем окнам
context.subscriptions.push(mod.onRequest(async (method, body) => ({ saved: true })));
mod.active;                                        // модуль найден и разрешён
mod.readData(); mod.writeData({ cfg: {} });        // тот же файл данных модуля
```

Окон VS Code может быть несколько, и каждое окно слушает все хосты. События с
`scope: "window"` (ветка git, ошибки, язык файла) получает только окно своего хоста: пару окно
находит по фокусу. Событие до 256 КБ, последние 32 события модуля запоминаются и сразу
приходят в новое окно. Запрос `rpc` идёт сначала своему хосту.

**Файл данных модуля** — `<globalStorage Moon Core>/modules/<id>.json`, объект до 1 МБ. Окно
читает его синхронно при старте (раньше, чем появится мост), пишет через мост; расширение
модуля читает и пишет напрямую. Сюда модуль кладёт то, что должно пережить очистку
`localStorage` окна, например свой конфиг.

Связь окна с расширением:

- при старте окно читает `mooncore-state.json` по `vscode-file://`, поэтому стили есть сразу, ещё до подключения;
- затем оно подключается к мосту **каждого** открытого окна VS Code (список в `mooncore-bridge.json`), так что правка из любого окна видна во всех;
- команды из JS-сниппетов выполняет хост того окна, которое в фокусе.

Соседство: Moon Core трогает только свой блок между `<!-- MOONCORE-START -->` и
`<!-- MOONCORE-END -->` и в CSP — только своё: nonce, порты моста и имя политики Trusted Types
`mooncore`; при снятии оболочка возвращается байт в байт. Блоки custom-css и cpp-docs-panel не меняются.

## Безопасность

- Мост слушает только `127.0.0.1`, принимает запросы только со случайным токеном (48 hex), с Origin оболочки VS Code и правильным Host (защита от сайтов и DNS-rebinding).
- Сниппеты берутся только из `globalStorage`, из папки проекта ничего не исполняется.
- Команды VS Code из JS-сниппетов: каждая новая — только после согласия («Разрешить всегда» запоминается, «Запретить» действует до конца сессии). Заранее разрешённые — `moonCore.allowedCommands`, выключить совсем — `moonCore.allowCommands`.
- Импорт вида (файл или синхронизация) проходит те же проверки, что и правки из окна: селекторы и значения CSS, настройки только из каталога, имена, лимиты.
- Конструктор меняет только настройки из каталога и только допустимыми значениями; CSS-значения и селекторы проверяются, в стиль не попадёт чужой код.
- JS-сниппеты исполняются с правами интерфейса VS Code. Не вставляй туда код, которому не доверяешь.
- Модули тоже исполняются с правами интерфейса, поэтому ни один не встраивается без согласия. Скрипт и ресурсы модуля берутся только из его папки, путь наружу (`..`, симлинки) отвергается; объём ограничен (4 МБ на модуль, 12 МБ на все, до 16 модулей).

## Настройки

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `moonCore.livePreview` | `true` | Живой предпросмотр несохранённого CSS |
| `moonCore.allowCommands` | `true` | Разрешить `mc.command` (каждая новая команда — после согласия) |
| `moonCore.allowedCommands` | `[]` | Команды, которые можно без вопроса |
| `moonCore.autoProfiles` | `[]` | Профили по контексту (язык, папка, ветка, тема, время суток) |
| `moonCore.autoProfileDefault` | `""` | Профиль, когда ни одно правило не подошло |
| `moonCore.sync` | `false` | Синхронизировать вид через Settings Sync (`moonCore.syncData`) |
| `moonCore.autoUpdateInjection` | `true` | Обновлять рантайм в оболочке при новой версии расширения и при изменении модулей |
| `moonCore.modules` | `[]` | Папки модулей (в каждой `mooncore-module.json`) |
| `moonCore.lazyUi` | `true` | Конструктор и пипетка грузятся при первом открытии, в оболочке — только ядро |

## Разработка

Рантайм окна правится в `extension/runtime/src/`, потом собирается:

```bash
npm run build
```

```bash
npm test
```

sha256) и в его отдельной копии проходит внедрение, работу в окне и снятие. Твой VS Code не
трогается, окна тестовой копии на минуту появятся на экране.

```bash
npm run e2e
```

```bash
node test/serve.js
```

Второе поднимает `http://localhost:8792/test/fixture.html`: рантайм на макете интерфейса VS Code
плюс настоящий мост с фейковым хостом, так что конструктор и пипетка сохраняют правки как в редакторе

событие ему отправляет `/test/publish?event=live&scope=window&data={...}`, итог лежит в `__DEMO__`. В консоли браузера доступен `__MOONCORE__`:
