## Быстрый старт

```bash
npm run package                                   # собрать dist/moon-core-<версия>.vsix
code --install-extension dist/moon-core-0.1.0.vsix
```

Перезапусти VS Code: при первом запуске Moon Core сам встроится в оболочку (пути к VS Code и
к своим данным он находит сам, настраивать ничего не нужно) и предложит перезагрузить окно.
Конструктор — кнопка на панели Moon Core или `Moon Core: Конструктор интерфейса`.

Отдельно:

```bash
npm run build            # собрать рантайм окна из частей extension/runtime/src/
npm test                 # все тесты (207 проверок, VS Code не нужен)
npm run e2e              # прогон в настоящем VS Code (скачивается один раз в .vscode-test/)
```

Удалить: `Moon Core: Убрать из VS Code`, затем `Ctrl+Shift+X` → «Moon Core» → Uninstall.

> Расширение раздаётся собственным `.vsix`, в маркетплейсе его нет: оно правит файлы самого
> VS Code, а такое Marketplace не пропускает. Подробности и риски — в [SECURITY.md](SECURITY.md).

## Что это

Платформа кастомизации и внедрения в интерфейс VS Code. Расширение (хост) плюс рантайм,
впечатанный прямо в оболочку редактора (`workbench.html`). Поэтому Moon Core умеет то, чего
нет в API расширений: менять и дополнять любой элемент интерфейса. При этом он не теряет
доступа к API: команды, файлы и редактор остаются под рукой.

Локальное расширение (`.vsix`), не для Marketplace. Ноль зависимостей.

| | Настройки VS Code | Custom CSS and JS Loader | Moon Core |
|---|---|---|---|
| Менять любой элемент окна | нет (только то, что вынесено в настройки) | да, руками в CSS | **да — кликом по элементу** |
| Без написания кода | да | нет | **да — конструктор, профили, галерея стилей** |
| Отмена правок | по одной настройке | нет | **да — история до 40 шагов, резервные копии вида** |
| Живой предпросмотр CSS | — | нет (перезагрузка окна) | **да — на каждый символ** |
| Баннер «установка повреждена» | — | да | **нет — хэш оболочки пересчитывается** |
| После обновления VS Code | — | включать заново руками | **встраивается сам, правки чинятся по отпечаткам** |
| Если что-то сломалось | — | править файлы руками | **стоп-кран, безопасный режим, Доктор, аварийное восстановление** |
| Внешние зависимости | — | — | **нет (0 npm-пакетов)** |

## Конструктор

Главное в Moon Core. Команда `Moon Core: Конструктор интерфейса` (или кнопка на панели Moon Core,
или меню по клику на «Moon» в статусбаре) превращает окно VS Code в редактируемый макет:

- навёл — элемент подсвечен и подписан («Миникарта», «Вкладка», «Пункт статусбара»);
- кликнул — открывается панель свойств этого элемента;
- Alt+клик — обычный клик (открыть меню, переключить вкладку), не выходя из конструктора.

Что можно сделать с элементом:

| Раздел | Что внутри |
|---|---|
| **Настройки VS Code** | Если для элемента есть штатная настройка (миникарта, хлебные крошки, вкладки, панель активности, центр команд, размер шрифта кода, терминал...), она показана первой. Это надёжный способ: переживает обновления. |
| **Вид** | Скрыть, прозрачность, фон, скругление |
| **Размер** | Масштаб (`zoom`), внутренний отступ; отдельно ширина и высота |
| **Текст** | Размер шрифта, жирность, шрифт, цвет |

Правка видна сразу, сохраняется сама и попадает во вкладку **«Правки»**. Там весь список
того, что ты поменял, и у каждого пункта есть крестик «вернуть как было». Для настроек VS Code
запоминается исходное значение, и при отмене возвращается именно оно. Скрытые элементы
возвращаются тоже отсюда.

### Прямо на элементе

У выбранного элемента на рамке есть ручки: тяни мышкой, значение видно рядом.

| Ручка | Что меняет |
|---|---|
| правый край, низ, угол | ширину и высоту |
| кружок сверху справа | масштаб |
| квадрат снизу слева | внутренний отступ |
| «::» сверху слева | место среди соседей (перетащи; вставка показана линией) |

Двойной клик по ручке возвращает как было. Порядок работает для элементов в ряду: пункты
статусбара, иконки панели активности, кнопки. Во вкладке «Элемент» для них есть секция «Порядок»
(раньше, позже, как было), а на «Карте» строки поштучных списков тоже перетаскиваются.

**«Как было»** в нижней полосе конструктора: пока кнопка нажата, окно показано без правок CSS
(до / после). Настройки VS Code при этом не переключаются.

Во вкладке «Правки» наведение на правку обводит её элементы в окне, а скрытые этой правкой
элементы на это время показываются. На «Карте» наведение подсвечивает элемент.

### Цвета темы

Выбрал элемент — секция «Цвета темы» показывает, какой цвет темы его красит (например
`statusBar.background`), и меняет его через штатную настройку `workbench.colorCustomizations`.
Это надёжнее CSS: переживает обновления и меняет цвет везде, где тема его использует. Для текста
кода (элемент «Текст кода») есть «Цвета кода»: комментарии, строки, ключевые слова, числа, типы,
функции, переменные. Всё отменяется во вкладке «Правки», прежние значения возвращаются.

### Когда применять

Любую правку можно ограничить: только в языке (markdown), только на ветке, только в проекте,
только в светлой или тёмной теме — секция «Когда применять». Например: миникарта спрятана только
в markdown, красный статусбар только на ветке main. Это работает и в CSS-сниппетах:
`html[data-mc-lang="markdown"] .minimap { display: none; }`.

### Вкладка «Ещё»

- **Свои кнопки**: любая команда VS Code — кнопкой в статусбаре, титлбаре или над редактором.
  Команду выбираешь в списке VS Code, дальше значок, подпись и место.
- **Эффекты редактора**: след за курсором, искры при наборе, свечение строки и курсора; рядом
  плавный курсор, его форма и мигание, плавная прокрутка, лигатуры.
- **Отдельные окна**: редактор или группу — в отдельное окно VS Code (например, на второй монитор).

Любой элемент можно ещё и **открепить** прямо в этом окне: «Элемент» → «Плавающее окно».

### Глубокая интеграция

Команда `Moon Core: Глубокая интеграция`, обе части по умолчанию выключены:

| Часть | Что даёт | Что правится |
|---|---|---|
| **Сервисы окна** | Moon Core и модули получают настоящие сервисы окна VS Code: `mc.service("statusbarService")`, `codeEditorService`, `commandService`... | одна строка в `workbench.desktop.main.js` (бэкап рядом, хэш в `product.json` пересчитывается) |
| **Главный процесс** | `Moon Core: Вид окна`: непрозрачность окна, «поверх всех окон», акрил или слюда Windows 11, vibrancy macOS | импорт в `out/main.js` (в контрольные суммы не входит) и `mooncore-main.mjs` |

После включения нужен полный перезапуск VS Code (закрыть все окна). Сервисы окна — внутренний
API VS Code: он меняется между версиями, поэтому `mc.service` может вернуть `null`, а форма
объекта — отличаться. Материал Windows 11 виден там, где интерфейс прозрачный (например, с
MoonLight BG). «Убрать из VS Code», хук удаления и `moon-core-restore.cmd` снимают и эти патчи.

### Самолечение после обновлений VS Code

К каждой правке Moon Core запоминает отпечаток элемента: запасные селекторы (id, aria-label,
title), текст, классы, запись каталога. Если VS Code переименовал классы и правка перестала
что-либо находить, проверка селекторов ищет элемент по отпечатку и предлагает замену: кнопка
«Починить» после обновления VS Code, в «Проверить селекторы» и в «Докторе». Принятая замена
переносит правило на новый селектор и во всех своих профилях.

### Карта интерфейса

Вкладка **«Карта»** открывается первой: всё, что есть в окне VS Code, по зонам (окно, титлбар,
панель активности, боковая панель, редактор, нижняя панель, статусбар).

- галочка показывает или скрывает элемент: миникарту, хлебные крошки, центр команд, кнопки раскладки, полосу вкладок и т.д.;
- пункты статусбара и иконки панели активности перечислены **поштучно**, ненужные снимаются галочкой;
- «Настроить» открывает все свойства элемента, даже если его сейчас нет на экране (например, «Масштаб окна»).

Где возможно, галочка переключает настройку VS Code, иначе ставит правило «скрыть». Если
включить элемент обратно, вернётся то значение, что было до тебя.

### Профили вида

Вкладка **«Профили»** (или команда `Moon Core: Профили вида`, быстрый выбор списком):

- **встроенные:** «Минимал» (без второстепенных кнопок и панелей), «Только код» (ещё и без панели активности, статусбара и полей), «Крупный» (масштаб и шрифты больше);
- **свои:** настроил вид и нажал «Сохранить» под своим именем;
- **«Исходный вид VS Code»** снимает все правки.

Применение профиля заменяет текущие правки (перед этим спрашивается подтверждение). Настройки
всегда откатываются к исходным значениям VS Code, а не к прошлому профилю, поэтому «Исходный вид»
после любых переключений возвращает VS Code ровно к тому, каким он был. Если после применения
профиля что-то поменял, это видно («изменён»), и профиль можно «Обновить».

### Профили по контексту

Профиль может включаться сам — по языку открытого файла, папке проекта, git-ветке, виду
темы или времени суток. Правила — в `settings.json`, первое подходящее выигрывает:

```jsonc
"moonCore.autoProfiles": [
  { "profile": "Только код", "languages": ["markdown"] },
  { "profile": "Минимал", "folders": ["work-*"], "branches": ["release/*"] },
  { "profile": "Ночь", "time": "22:00-07:00" },          // можно через полночь, можно списком
  { "profile": "Светлый", "themes": ["light"] }           // dark, light, highContrast, highContrastLight
],
"moonCore.autoProfileDefault": ""   // профиль, когда ничего не подошло (пусто — не менять)
```

Внутри правила все условия должны совпасть, внутри списка — любое; в папках и ветках работает
`*`. Профиль и настройки VS Code общие для всех окон, поэтому решает окно в фокусе. Если в
конструкторе есть несохранённые правки, профиль не переключится (сообщение в статусбаре): сохрани
их в профиль, и авто-переключение продолжит работать.

### Профиль проекта

Вид может ехать вместе с репозиторием: файл `.vscode/mooncore.json` в папке проекта.

```jsonc
{ "mooncore": 1, "note": "Для ревью", "use": "Минимал" }                 // включить готовый профиль
{ "mooncore": 1, "note": "...", "rules": { ... }, "settings": { ... } }   // или свой вид
```

При первой встрече с файлом Moon Core спросит, включать ли его (изменился файл — спросит
снова). Свой вид проекта хранится как профиль «Проект <папка>». Файл проходит те же проверки,
что и профиль, а части модулей из проекта не берутся. Профиль проекта важнее правил
`autoProfiles`. Команда `Moon Core: Сохранить вид в проект` пишет текущие правки в этот файл.

### Профиль и модули

Профиль хранит не только правки интерфейса, но и состояние модулей, которые это умеют. Например,
MoonLight BG кладёт в профиль свой образ фона: «Только код» может заодно включать спокойный
фон, а профиль по ветке — свой набор. На карточке профиля это видно («+ MoonLight BG»).

### Отмена, копии и страховки

| Что | Как |
|---|---|
| **Отменить / вернуть** | Кнопки в нижней полосе конструктора, `Ctrl+Z` / `Ctrl+Y` в режиме конструктора, команды `Moon Core: Отменить последнюю правку конструктора`. История — до 40 шагов; движение ползунка — один шаг. Отмена возвращает и настройки VS Code, и цвета темы. |
| **Резервные копии вида** | Перед применением профиля, сбросом и загрузкой вида из файла текущий вид сам уходит в копию (хранится 12 последних). `Moon Core: Восстановить вид из резервной копии`. |
| **Стоп-кран** | `Ctrl+Alt+Shift+Backspace` выключает (и включает) все стили Moon Core в этом окне. Работает без связи с расширением: если правка спрятала нужное, до конструктора всегда можно добраться. |
| **Безопасный режим** | `Moon Core: Безопасный режим` (`Ctrl+Alt+Shift+F12`): сниппеты, правки конструктора, эффекты и модули отключены во всех окнах, ничего не удаляется. В статусбаре и в углу окна — напоминание. |
| **Страж** | Скрыть корень окна (`body`, `.monaco-workbench`, сетку частей), область редактора или интерфейс самого Moon Core конструктор не даст — ни из окна, ни из профиля, ни из загруженного файла. |
| **Падающий сниппет** | JS-сниппет, который сыплет ошибками без остановки, останавливается в окне сам и запускается снова, когда поправишь код. |
| **Повреждённый файл правок** | Нечитаемый файл правок не затирается пустым видом: он откладывается как `.corrupt`, вид берётся из последней копии. |

### Быстрее и удобнее

- **Быстро**: у выбранного элемента — «Скрыть», «Крупнее», «Мельче», «Прозрачнее» одной кнопкой.
- **Скопировать стиль / Вставить стиль**: правки одного элемента переносятся на другой.
- **Поиск по карте**: поле над списком ищет по названиям элементов и их настроек.
- **Клавиши конструктора**: стрелка вверх — родитель, вниз — обратно, `Delete` — скрыть, `Esc` — выйти.
- **Панель помнит** своё место и вкладку; двойной клик по заголовку возвращает её на место.
- **Новые свойства**: рамка (толщина и цвет), тень, размытие под элементом, обесцвечивание, внешний
  отступ, межбуквенный интервал, высота строки, регистр текста.
- **Вид интерфейса** (вкладка «Ещё»): акцентный цвет одним щелчком (цвета темы VS Code), шрифт
  интерфейса, скругление, плавные переходы, приглушение неактивных редакторов.
- **Шрифты кода и терминала** — прямо в конструкторе (настройки `editor.fontFamily`,
  `terminal.integrated.fontFamily`).
- **Каталог**: 49 элементов VS Code (было 31) — центр уведомлений, палитра команд, меню,
  разделители, проводник, поиск, расширения, вторая боковая панель, активная вкладка, текущая
  строка, подсказки, окно поиска, панель отладки.
- **Профили**: к «Минимал», «Только код», «Крупный» добавлены «Дзен», «Презентация», «Компактный».
- **Галерея стилей** (`Moon Core: Галерея готовых стилей`): «Фокус на коде», «Стеклянные окна»,
  «Мягкие тени», «Заметная активная вкладка» и другие (15 штук) — галочками, без кода. Каждый стиль —
  обычный файл в «Сниппетах».
- **Панель «Вид»** в боковой панели Moon Core: состояние, профили (клик — применить), действия.
- **Стили внутри webview** (`Moon Core: Стили внутри webview`): сниппеты с именем `webview*.css`
  применяются не к окну, а внутри страниц расширений и превью Markdown. По умолчанию выключено; файл
  VS Code, уже изменённый другой программой, Moon Core не трогает.
- **Все значки VS Code** для своих кнопок и **любой цвет темы** — поиском по имени (вкладка «Ещё»).
- **Целостность файлов VS Code** в Докторе: какие файлы изменены только Moon Core, какие — кем-то
  ещё, и что осталось в папке VS Code от других загрузчиков.
- **«Точно сломано»**: проверка элементов отличает переименованный класс от элемента, который
  просто не показан, — по файлам самой установки VS Code.
- **Несколько элементов сразу**: Shift+клик добавляет элемент к выбранным; «Похожие (N)» берёт все
  элементы с тем же классом; «Скрытое» в полосе конструктора показывает скрытые элементы, чтобы их вернуть.
- **Подсказки в CSS-сниппете**: классы VS Code после точки и цвета темы после `--` — из файлов твоей
  версии VS Code.
- **Выключить правку, не удаляя**: во вкладке «Правки» у каждой правки — «Выключить» / «Включить».
- **Состояние**: правка только под мышью, в фокусе или пока элемент нажат.
- **Пипетка и палитра** у полей цвета: цвет с экрана, недавние цвета, цвета темы.
- **Часть профиля**: взять из профиля только цвета, настройки, элементы, эффекты или кнопки;
  профиль можно переименовать; `Moon Core: Следующий профиль вида` переключает по кругу.
- **Вид через буфер обмена**: скопировать правки и профили текстом и вставить на другом компьютере.
- **Предпросмотр в галерее**: стиль под курсором списка виден в окне сразу.
- **Переезд с Custom CSS and JS Loader**: `Moon Core: Перенести файлы из Custom CSS and JS Loader`.

### Мелочи

Однотипные элементы (вкладки, пункты статусбара, иконки) по умолчанию меняются по одному.
Кнопка «Все такие» применяет правку ко всем элементам этого типа. «Родитель» поднимается на
уровень выше, если кликнул в мелкую деталь.

Сбросить всё: кнопка «Сбросить всё» во вкладке «Правки» или команда
`Moon Core: Сбросить изменения конструктора`.

| **Самовосстановление** | Если VS Code перестроил DOM, стили возвращаются. Если VS Code обновился и оболочка пересоздана, при запуске появится предложение внедрить заново. Новая версия рантайма обновляется в оболочке автоматически. |
| **Команды из интерфейса** | `mc.command('workbench.action.terminal.toggleTerminal')`: кнопка, встроенная в интерфейс, вызывает команду VS Code. Каждую новую команду Moon Core сначала спросит. |

## Скорость VS Code

`Moon Core: Скорость VS Code` (меню «Moon» в статусбаре, панель «Вид», Доктор) — что тормозит запуск
именно у тебя. Moon Core работает и в процессе расширений, и в самом окне, поэтому меряет то, чего не
видит внешний лаунчер, — по меткам, которые VS Code ставит сам:

| Раздел | Что показывает |
|---|---|
| **Запуск окна** | когда отрисован интерфейс и когда поднялись расширения, сравнение с обычным, последние 20 запусков, этапы: загрузка кода, хранилище, папка и настройки, отрисовка, редакторы, расширения |
| **Советы** | только по фактам и с кнопками «Применить» / «Вернуть как было»: не следить за тяжёлыми папками проекта (`node_modules`, `.venv`, кэши сборки), поиск без перехода по ссылкам, лимит вкладок при долгом восстановлении редакторов, медленные расширения — в отдельный процесс |
| **Расширения этого окна** | загрузка кода и `activate()` каждого расширения в этом запуске, среднее по прошлым запускам и когда оно включается; «при старте (*)» выделено — такие удобнее выключить для папок, где они не нужны |
| **Подвисания и память окон** | сколько раз главный поток окна вставал дольше 200 мс, самое долгое, память JS |
| **Сам Moon Core** | его собственная активация и время рантайма в окне |

Если запуск стал заметно медленнее обычного (в полтора раза и на секунду, нужно от пяти прошлых
запусков), Доктор напишет об этом, а окно один раз в сутки предложит посмотреть, что тормозит
(`moonCore.speedNotify`).

Замеры копятся в `mooncore-perf.json` в папке данных расширения. Поле `export` (схема
`moon-core/perf@1`) — для внешних программ: например, VS Code Launcher может выбирать, какие стеки
расширений отключать, по реальной стоимости каждого расширения на старте. Команда «Сохранить замеры
скорости в файл» кладёт тот же JSON куда скажешь.

## Установка

```bash
npm test
npm run package
code --install-extension dist/moon-core-0.1.0.vsix
```

При первом запуске расширение само внедряет рантайм в оболочку и предлагает перезагрузить окно
(`moonCore.autoInject`; выключишь — будет спрашивать). Если VS Code стоит в Program Files, Windows один
раз попросит права администратора. Вручную — команда `Moon Core: Внедрить в VS Code`. После перезагрузки окна VS Code может написать, что установка
«повреждена» — Moon Core сам пересчитывает хэш оболочки в `product.json` (`moonCore.fixChecksum`),
поэтому баннера нет. Раньше это было ожидаемо для любого патча оболочки (так же работают custom-css и
cpp-docs-panel), и на работу редактора не влияет.

Снять: `Moon Core: Убрать из VS Code`. При удалении расширения блок снимается сам (хук `vscode:uninstall`).


### Надёжность внедрения

| Что | Как |
|---|---|
| **Нет баннера «повреждена»** | Хэш оболочки в `product.json` пересчитывается при записи и возвращается при снятии (`moonCore.fixChecksum`). |
| **После обновления VS Code** | Moon Core встраивается заново сам (`moonCore.autoReinject`, по умолчанию включено) — остаётся перезагрузить окно. Выключишь — будет спрашивать. |
| **Модули файлами** | `mooncore-mod-<id>.js` рядом с оболочкой вместо инлайна (`moonCore.moduleFiles`): оболочка лёгкая, скрипт кэшируется. |
| **Защита запуска** | Если окно не запустилось на модуле, в следующий раз он пропускается (с уведомлением); после перезагрузки — снова пробуется. |
| **Если VS Code не открывается** | Закрой VS Code и запусти `moon-core-restore.cmd` из папки данных расширения (`%APPDATA%\Code\User\globalStorage\moonlivedt.moon-core\`): блок снимется, хэш вернётся. Путь есть в диагностике. |
| **VS Code в Program Files** | Вместо ошибки «нет прав» — одна запись с правами администратора (UAC). Пишет сам VS Code в режиме Node, PowerShell не нужен; если Windows не даёт запросить права автоматически (запуск PowerShell и Windows Script Host запрещён политикой), Moon Core откроет папку с `run.cmd` — запусти его «от имени администратора». Совсем без администратора — VS Code вариантом User Installer (кнопка «Без администратора»). |
| **Время запуска** | `Moon Core: Диагностика` показывает, сколько миллисекунд стартовали рантайм и каждый модуль. |
| **Окно сессий** | `moonCore.injectSessions` — встраивать и в окно агентских сессий (VS Code 1.121+). |
| **Несколько окон сразу** | Оболочку пишет одно окно за раз (блокировка `mooncore-inject.lock` в папке данных): после обновления VS Code окна не перемешивают записи, остальные дожидаются первого и видят, что всё уже сделано. |
| **Лёгкий старт окна** | В оболочку встраивается только ядро (~130 КБ из 250): конструктор и пипетка лежат файлом в папке данных и грузятся при первом открытии (`moonCore.lazyUi`). Файл сверяется по SHA-256, для Trusted Types VS Code в CSP добавляется политика `mooncore`. Если какой-то VS Code так загрузить не даст, Moon Core сам встроит интерфейс целиком. |


### Безопасность

Moon Core исполняет код в окне VS Code, поэтому ничего не встраивается и не запускается молча:

- **модули** — каждый новый спрашивает разрешения, а изменённый код модуля встраивается только
  после «Встроить» (для своей папки разработки — «Всегда доверять этой папке»);
- **JS-сниппеты** — запускается только код, который ты видел: сохранённый в VS Code, созданный
  командой или загруженный с подтверждением;
- **оболочка** — хэш в `product.json` пересчитывается, только если в ней нет чужих вставок или
  ты их одобрил: баннер «повреждена» не прячет чужое вмешательство;
- **права администратора** — повышенно запускается системный `cmd.exe` и VS Code (из Program Files),
  а не скрипт из папки пользователя; хэши кода записи и задания передаются прямо в командной строке,
  каждый файл данных сверяется по SHA-256 до записи — подменить их нельзя, при сбое запись откатывается;
- **команды из окна** — каждая новая с согласия; опасные (текст в терминал, установка расширений,
  git push/clean, удаление файлов, внутренние `_…`) — модально при каждом вызове, без «всегда»;
- **модули и шлюз к VS Code** — модуль не читает настройки с секретами, не открывает файлы вне
  проекта без вопроса, все его уведомления и вопросы подписаны его именем, один вопрос за раз;
- **профиль проекта** — в недоверенной папке (Restricted Mode) даже не предлагается;
- **запись оболочки** — перед записью результат проверяется: кроме блока Moon Core и CSP в оболочке
  не меняется ничего, блок один и лежит в `<head>`; иначе запись не делается;
- **загрузка чужого вида** — если стили пакета обращаются в сеть, в подтверждении перечислены адреса
  (такой стиль сообщал бы автору твой IP при каждом запуске VS Code);
- **журнал разрешений** — «Moon Core: Разрешения» показывает, что и когда разрешено, «Отозвать все
  разрешения» сбрасывает их разом;
- **мост** — только 127.0.0.1, порты 47300–47319, токен на каждый запуск, проверка Origin и Host,
  лимит частоты; в CSP разрешены только эти порты;
- настройки, дающие выполнить код, в Settings Sync не попадают; в журнале нет имени пользователя,
  токенов моста, ключей API и паролей (журнал дублируется в файл `mooncore.log` в хранилище).

## Сниппеты

Панель **Moon Core** на боковой панели активности:

- галочка включает или выключает сниппет;
- клик открывает сниппет в редакторе;
- кнопки сверху: пипетка, новый CSS, новый JS, проверка селекторов;
- в меню `...` есть папка сниппетов, диагностика, внедрение и снятие.

Файлы лежат в `globalStorage` расширения (`snippets/*.css`, `snippets/*.js`). Порядок
применения CSS совпадает с порядком имён, так что каскад предсказуем (`00-base.css`, `10-tabs.css`, ...).
Пипетка складывает скрытые элементы в `hidden.css`, а заготовки стилей — в активный
CSS-сниппет или в `picked.css`.

### Помощник `mc` в JS-сниппетах

```js
mc.watch(selector, el => { ... })   // для каждого элемента по селектору, в том числе будущих
mc.el(tag, props, children)         // создать элемент
mc.mount(parent, node)              // вставить (уберётся при выгрузке)
mc.css(text)                        // добавить стиль
mc.on(target, event, fn)            // подписка
mc.every(ms, fn) / mc.after(ms, fn) // таймеры
mc.command(id, ...args)             // команда VS Code, Promise
mc.toast(text)                      // короткое сообщение
mc.onDispose(fn)                    // своя уборка
mc.$(sel) / mc.$$(sel)              // поиск элементов
```

Пример: кнопка в статусбаре, которая открывает терминал.

```js
mc.watch('.statusbar .right-items', (bar) => {
    const btn = mc.el('div', { className: 'statusbar-item', textContent: 'TERM', title: 'Терминал' });
    btn.style.cursor = 'pointer';
    mc.on(btn, 'click', () => mc.command('workbench.action.terminal.toggleTerminal'));
    mc.mount(bar, btn);
});
```

Ошибки сниппетов попадают в журнал (`Moon Core: Показать журнал`) и показываются уведомлением
с кнопкой «Открыть».

## Модули

Модуль — рантайм другого плагина, который Moon Core впечатывает в оболочку VS Code своим
блоком, сразу после собственного рантайма. Модулю не нужен ни свой патч `workbench.html`, ни
be5invis / custom-ui-style: внедрение, nonce в CSP, обновление после апдейта VS Code и снятие
при удалении делает ядро.

### Как объявить модуль

Из расширения: в его `package.json`

```json
"moonCore": {
  "modules": [
    { "id": "mlbg", "name": "MoonLight BG", "version": "20.0.0", "script": "custom-bg.js", "assets": "." }
  ]
}
```

Из папки (удобно при разработке): положить в папку `mooncore-module.json` с тем же объектом
и добавить путь к папке в настройку `moonCore.modules`.

| Поле | Что это |
|---|---|
| `id` | `^[a-z][a-z0-9-]{1,31}$`, уникальный |
| `script` | рантайм модуля, путь внутри папки модуля (наружу через `..` и симлинки нельзя), до 4 МБ |
| `assets` | папка ресурсов внутри модуля (по умолчанию корень), окно получит её адрес |
| `trustedTypes` | свои политики Trusted Types (до 4 имён): Moon Core впишет их в CSP оболочки. Нужно, если модуль вызывает `trustedTypes.createPolicy` — в VS Code с CSP иначе вызов упадёт |
| `name`, `version` | для людей и диагностики |
| `capabilities` | права сверх базовых: `editor.read` (слово и выделение под курсором, путь файла, тексты ошибок, подсказки языкового сервера), `decorations` (подсветка кода), `layout` (показать и скрыть части окна). Одобряются вместе с модулем; новые права в обновлении — отдельный вопрос |
| `lazy` | `true` или `{ "delay": 5000 }`: файл модуля не грузится при старте окна — только по его команде, по `mc.load(id)` или через `delay` мс |
| `commands` | `[{ "id": "open", "title": "Документация", "langs": ["cpp"], "context": true }]` — команды в «Moon Core: Команды модулей» и (при `context`) в контекстном меню редактора |

Каждый новый модуль встраивается только после согласия: Moon Core спросит один раз. Исключение — модули расширений того же издателя (moonlivedt.*: фон, окно документации): это части одного набора, они разрешаются сами.
Разрешение привязано к id и источнику: тот же id из другого места спросит заново.
Команда `Moon Core: Модули` включает и выключает модули списком. Пересобрал рантайм модуля,
и Moon Core сам обновит блок и предложит перезагрузить окно.

### Свой модуль: заготовка и режим разработки

`Moon Core: Создать модуль` делает папку с манифестом, заготовкой `runtime.js`, папкой
`assets`, типами `mooncore.d.ts` и `jsconfig.json` (подсказки в VS Code) и добавляет её в
`moonCore.modules`. Дальше — `Moon Core: Модули`, чтобы разрешить.

`Moon Core: Режим разработки модуля` (до перезапуска VS Code): сохранил код модуля — он сразу
перезапускается в открытых окнах, без вопроса и без перезагрузки. Перед перезапуском модуль
должен убрать за собой всё, что создал: `mc.onDispose(fn)`; номер перезапуска — `mc.hot`.
Типы всего API — в `extension/types/mooncore.d.ts`.

### В окне: помощник модуля

```js
var mc = window.__MOONCORE__ && window.__MOONCORE__.module("mlbg");
if (mc) {
    mc.base;                                   // адрес папки ресурсов, со слэшем на конце
    var off = mc.on("live", function (d) {});  // событие от своего расширения (последнее значение придёт сразу)
    mc.get("live");                            // последнее значение или undefined
    mc.rpc("save", { a: 1 }).then(function (r) { /* {ok, result} или {ok:false, error} */ });
    mc.log("где", err);                        // в журнал Moon Core
    mc.profile({ save: () => ({}), apply: (obj, name) => {} });   // своя часть в профилях вида
    mc.data();                                 // файл данных модуля: синхронно при старте (объект или null)
    mc.saveData({ cfg: {} });                  // сохранить файл данных (через мост, пишет хост)
    mc.onDispose(function () {});              // уборка перед горячей перезагрузкой (режим разработки)
    mc.hot;                                    // сколько раз модуль перезапущен (0 — обычный запуск)
    mc.connected();                            // есть ли связь с расширением

    // Настоящий API VS Code через хост своего окна:
    mc.vscode.statusItem("sync", { text: "$(sync) 3", tooltip: "..." });   // элемент статусбара VS Code
    mc.on("nativeClick", function (d) { /* d.item === "sync" */ });
    mc.vscode.notify("Готово", { buttons: ["Открыть"] }).then(function (r) { /* r.result */ });
    mc.vscode.quickPick(["a", "b"]); mc.vscode.input("Имя?"); mc.vscode.open("C:/x.txt");
    mc.vscode.config("editor.fontSize"); mc.vscode.context();              // язык, ветка, проект, тема
}
```

Расширению, которому нужна только кнопка, свой модуль не нужен:

```js
const core = await vscode.extensions.getExtension("moonlivedt.moon-core").activate();
const b = core.ui("Моё расширение").button({ id: "run", zone: "titlebar", icon: "rocket", tooltip: "Запуск", command: "my.run" });
b.dispose();                                       // убрать
```

### VS Code для модулей

Модуль видит, что происходит в VS Code, и добавляет в него своё — настоящим API, а не вёрсткой.

```js
// События редактора своего окна (текущее значение приходит сразу):
// editor, cursor, save, diagnostics, debug, terminal, task, git, theme.
mc.vscode.on("cursor", function (d) { /* { line, col } и с правом editor.read — { word, selection, lineText } */ });
mc.vscode.on("diagnostics", function (d) { /* { errors, warnings, infos }, с editor.read — items */ });
mc.vscode.on("debug", function (d) { /* { active, name, type } */ });

// Код под курсором через языковой сервер (editor.read): word | hover | definition | symbols.
mc.vscode.symbol("hover").then(function (r) { /* r.result — текст подсказки clangd, tsserver... */ });

// Подсветка в активном редакторе (decorations): стиль — только #hex и значения из списков.
mc.vscode.decorate("errors", { backgroundColor: "#ff000022", after: { contentText: " ← здесь", color: "#888" } },
    [{ line: 12, hover: "подсказка при наведении" }]);
mc.vscode.undecorate("errors");
mc.vscode.tabs();                                   // открытые вкладки по группам

// Части окна: видимость и размеры — по вёрстке, переключение — командами VS Code (layout).
mc.layout.visible("sidebar"); mc.layout.sizes(); mc.layout.hide("panel"); mc.layout.toggle("zen");

// Команды модуля: «Moon Core: Команды модулей» и контекстное меню редактора.
mc.commands.register([{ id: "open", title: "Документация по символу", langs: ["cpp"], context: true }]);
mc.commands.on("open", function (ctx) { /* { lang, line }, с editor.read — word, selection, path */ });

// Плавающее окно: одно на id, перетаскивание, размер, прилипание к краям, место запоминается.
var win = mc.window({ id: "reader", title: "Документация", width: 480, height: 360 });
win.body.appendChild(document.createElement("div"));
win.dock("right"); win.onClose(function () {}); win.close();

// Общая шина модулей этого окна: значение с автором.
mc.share("accent", "#89b4fa");
mc.shared("accent", function (value, from) { /* from — id модуля-автора */ });

mc.load("other-module");                           // загрузить ленивый модуль
```

- Подписки на события идут всем хостам, применяются события только своего окна. Хост считает
  событие, только если на него кто-то подписан, и не шлёт одно и то же дважды.
- Права — ограничение шлюза: без `editor.read` модуль получает события без слова, выделения,
  пути и текстов ошибок, без `decorations` и `layout` — отказ. Код модуля в окне видит вёрстку и
  так; права делают явным, что модуль берёт у VS Code.
- Команды: манифест плюс `mc.commands.register` из окна. В контекстном меню редактора пункт
  появляется только в файлах тех языков, что указаны в `langs`. Нажатие — разовое событие: в новые
  окна не повторяется. Ленивый модуль сначала загружается, потом получает команду.
- Выключил модуль в `Moon Core: Модули` — окно убирает его сразу, без перезагрузки: его
  `onDispose`, подписки, окна, подсветка, значения в шине. Включил снова — тот же файл грузится
  заново. Модуль, которого не было в оболочке, требует перевнедрения и перезагрузки.
- Ленивый модуль грузится обычным `<script src>` с `integrity` через политику Trusted Types
  «mooncore» (она пропускает только файлы `mooncore-mod-*.js`). Если файл пропал или изменился
  (модуль обновило другое окно), окно берёт одобренный код у хоста.

Модуль, которого нет в списке разрешённых, помощника не получит (`module()` вернёт `null`).
Хорошо, если модуль умеет жить и без Moon Core: так проще переезжать.

### В расширении: API Moon Core

```js
const ext = vscode.extensions.getExtension("moonlivedt.moon-core");
const core = ext && await ext.activate();          // { apiVersion: 1, module(id) }
const mod = core.module("mlbg");
mod.publish("live", { branch: "main" }, { scope: "window" });   // только окну этого хоста
mod.publish("theme", "dark");                                   // всем окнам
context.subscriptions.push(mod.onRequest(async (method, body) => ({ saved: true })));
mod.active;                                        // модуль найден и разрешён
mod.readData(); mod.writeData({ cfg: {} });        // тот же файл данных модуля
```

Окон VS Code может быть несколько, и каждое окно слушает все хосты. События с
`scope: "window"` (ветка git, ошибки, язык файла) получает только окно своего хоста: пару окно
находит по фокусу. Событие до 256 КБ, последние 32 события модуля запоминаются и сразу
приходят в новое окно. Запрос `rpc` идёт сначала своему хосту.

**Файл данных модуля** — `<globalStorage Moon Core>/modules/<id>.json`, объект до 1 МБ. Окно
читает его синхронно при старте (раньше, чем появится мост), пишет через мост; расширение
модуля читает и пишет напрямую. Сюда модуль кладёт то, что должно пережить очистку
`localStorage` окна, например свой конфиг.

### Почему свой упаковщик

`.vsix` — это обычный ZIP с двумя служебными файлами в корне. Стандартный путь через
`@vscode/vsce` тянет npm-зависимости ради одной операции, поэтому ZIP пишется вручную поверх
встроенного `zlib`: у проекта ноль зависимостей, сборка работает сразу после клонирования.

### Как окно связано с расширением

Связь окна с расширением:

- при старте окно читает `mooncore-state.json` по `vscode-file://`, поэтому стили есть сразу, ещё до подключения;
- затем оно подключается к мосту **каждого** открытого окна VS Code (список в `mooncore-bridge.json`), так что правка из любого окна видна во всех;
- команды из JS-сниппетов выполняет хост того окна, которое в фокусе.

Соседство: Moon Core трогает только свой блок между `<!-- MOONCORE-START -->` и
`<!-- MOONCORE-END -->` и в CSP — только своё: nonce, порты моста и имя политики Trusted Types
`mooncore`; при снятии оболочка возвращается байт в байт. Блоки custom-css и cpp-docs-panel не меняются.

## Модель безопасности коротко

- Мост слушает только `127.0.0.1`, принимает запросы только со случайным токеном (48 hex), с Origin оболочки VS Code и правильным Host (защита от сайтов и DNS-rebinding).
- Сниппеты берутся только из `globalStorage`, из папки проекта ничего не исполняется.
- Команды VS Code из JS-сниппетов: каждая новая — только после согласия («Разрешить всегда» запоминается, «Запретить» действует до конца сессии). Заранее разрешённые — `moonCore.allowedCommands`, выключить совсем — `moonCore.allowCommands`.
- Импорт вида (файл или синхронизация) проходит те же проверки, что и правки из окна: селекторы и значения CSS, настройки только из каталога, имена, лимиты.
- Конструктор меняет только настройки из каталога и только допустимыми значениями; CSS-значения и селекторы проверяются, в стиль не попадёт чужой код.
- JS-сниппеты исполняются с правами интерфейса VS Code. Не вставляй туда код, которому не доверяешь.
- Модули тоже исполняются с правами интерфейса, поэтому ни один чужой не встраивается без согласия (свои, moonlivedt.*, разрешаются сами: расширение и так ставится с полным доступом к редактору). Скрипт и ресурсы модуля берутся только из его папки, путь наружу (`..`, симлинки) отвергается; объём ограничен (4 МБ на модуль, 12 МБ на все, до 16 модулей).

Полная модель угроз и как сообщить об уязвимости — в [SECURITY.md](SECURITY.md).

## FAQ / Решение проблем

**После правки пропало что-то нужное, до конструктора не добраться.**
`Ctrl+Alt+Shift+Backspace` — стоп-кран: выключает все стили Moon Core в этом окне, без связи с
расширением. Дальше — «Отменить» в конструкторе или `Moon Core: Восстановить вид из резервной копии`.

**Хочу понять, виноват ли Moon Core.**
`Moon Core: Безопасный режим` (`Ctrl+Alt+Shift+F12`): сниппеты, правки, эффекты и модули
отключаются во всех окнах, ничего не удаляется. Проблема осталась — дело не в Moon Core.

**VS Code пишет, что установка «повреждена».**
Moon Core пересчитывает хэш оболочки сам (`moonCore.fixChecksum`), но только если в оболочке нет
чужих вставок или ты их одобрил. `Moon Core: Доктор` покажет, какие файлы изменены и кем.

**После обновления VS Code правки пропали.**
Обновление пересоздаёт оболочку. Moon Core встраивается заново сам (`moonCore.autoReinject`) —
остаётся перезагрузить окно. Если VS Code переименовал классы, «Починить» в Докторе перенесёт
правки на новые селекторы по отпечаткам.

**VS Code не открывается.**
Закрой его и запусти `moon-core-restore.cmd` из папки данных расширения
(`%APPDATA%\Code\User\globalStorage\moonlivedt.moon-core\`): блок снимется, хэш вернётся.

**Windows просит права администратора.**
VS Code стоит в Program Files, и оболочку без прав не записать. Запись одна, через UAC. Совсем
без администратора — VS Code вариантом User Installer.

**VS Code стал медленно открываться.**
`Moon Core: Скорость VS Code`: какое расширение и какой этап запуска подорожали, подвисает ли окно и
какие настройки помогут — с кнопкой «Вернуть как было» у каждого совета. Свою долю Moon Core тоже
показывает там же.

**Нашёл баг или есть идея.**
Открой [issue](https://github.com/moonlivedt-oss/moon-core/issues) (приложи отчёт из Доктора:
«Скопировать отчёт») или зайди в [Discussions](https://github.com/moonlivedt-oss/moon-core/discussions).

## Сборка

Зависимостей нет, `npm install` не требуется — скрипты просто зовут `node` (нужен Node 22+).
Рантайм окна правится в `extension/runtime/src/`, потом собирается.

```bash
npm run build            # собрать рантайм окна из частей
npm test                 # сборка актуальна + смоук (159) + рантайм окна (48), VS Code не нужен
npm run package          # собрать dist/moon-core-<версия>.vsix
npm run e2e              # прогон в настоящем VS Code
node test/serve.js       # стенд: рантайм на макете интерфейса в браузере
```

При каждом `push` / `pull request` в `main` GitHub Actions прогоняет `npm test` на Windows и
Linux и собирает `.vsix`.

Прогон в настоящем VS Code: скачивает VS Code stable в `.vscode-test/` (один раз, со сверкой
sha256) и в его отдельной копии проходит внедрение, работу в окне и снятие. Твой VS Code не
трогается, окна тестовой копии на минуту появятся на экране.

Стенд `node test/serve.js` поднимает `http://localhost:8792/test/fixture.html`: рантайм на макете интерфейса VS Code
плюс настоящий мост с фейковым хостом, так что конструктор и пипетка сохраняют правки как в редакторе
(состояние хоста видно по `/test/log`). Настоящий модуль подключается так: `node test/serve.js --module ../vscode-bg`. На стенде есть демо-модуль `demo` (`test/fixture-module.js`):
событие ему отправляет `/test/publish?event=live&scope=window&data={...}`, итог лежит в `__DEMO__`. В консоли браузера доступен `__MOONCORE__`:
`startDesign()`, `startPick()`, `selectorFor(el)`, `info()`.

Как участвовать — [CONTRIBUTING.md](CONTRIBUTING.md). Что в планах — [IDEAS.md](IDEAS.md).

## Приватность

Moon Core **не ходит в сеть** и не собирает телеметрию. Мост между окном и расширением слушает
только `127.0.0.1`. Правки, профили и сниппеты лежат в `globalStorage` расширения на этой машине;
через Settings Sync они едут, только если включить `moonCore.sync`. В журнале нет имени
пользователя, токенов моста, ключей API и паролей.

Рантайм исполняется в оболочке VS Code — так Moon Core и меняет интерфейс. Поэтому код в окно
попадает только тот, что ты видел и одобрил: JS-сниппеты, модули и команды из окна спрашивают
согласия. Подробности — в [SECURITY.md](SECURITY.md).

## Ограничения

- Установка через собственный `.vsix`: расширение правит файлы VS Code, в Marketplace такое не
  пропускают. Обновление — собрать и поставить новый `.vsix`.
- Каталог элементов и селекторы привязаны к вёрстке VS Code: после его обновления часть правок
  может перестать находить элементы (проверка селекторов и «Починить» это ловят).
- Глубокая интеграция опирается на внутренний API VS Code: между версиями он меняется, поэтому
  обе части по умолчанию выключены.
- Запись с правами администратора и аварийный `moon-core-restore.cmd` рассчитаны на Windows;
  на Linux и macOS — `moon-core-restore.sh`.
- Интерфейс расширения — на русском.
