# Политика безопасности

## Как сообщить об уязвимости

Пожалуйста, **не открывай публичный issue** для проблем безопасности. Вместо этого:

- воспользуйся приватным каналом GitHub — вкладка **Security → Report a vulnerability**
  (GitHub Security Advisories) в этом репозитории;
- либо напиши автору через профиль [@moonlivedt-oss](https://github.com/moonlivedt-oss).

Опиши, что нашёл(ла), как воспроизвести и в чём потенциальный вред. Постараюсь ответить в
разумный срок; после исправления — упомяну тебя в благодарностях (по желанию).

## Что важно знать о модели угроз

Moon Core — не обычное расширение: он **впечатывает свой рантайм в оболочку VS Code**
(`workbench.html`) и исполняется там с правами интерфейса редактора. Это осознанный выбор —
иначе нельзя менять произвольные элементы интерфейса, — поэтому защита строится вокруг того,
чтобы в оболочку попадал только код, который ты видел и одобрил.

**Что попадает в оболочку**

- Свой блок между `<!-- MOONCORE-START -->` и `<!-- MOONCORE-END -->`. В CSP добавляется только
  своё: одноразовый nonce, порты моста (47300–47319) и политика Trusted Types `mooncore`. CSP не
  снимается. Снятие возвращает оболочку байт в байт; чужие блоки (custom-css и др.) не трогаются.
- Хэш оболочки в `product.json` пересчитывается, только если в ней нет чужих вставок или ты сам их
  одобрил: иначе баннер «установка повреждена» остаётся — он предупреждает о вмешательстве.
- Отпечаток записанного блока запоминается: если блок поменял кто-то другой, Moon Core предупредит
  и перепишет его.
- Запись с правами администратора (VS Code в Program Files): повышенно запускается системный
  `cmd.exe` из `%SystemRoot%\System32` и исполняемый файл VS Code в режиме Node — ничего из папки
  пользователя, что можно было бы подменить до согласия в окне UAC. Загрузчик получает SHA-256 кода
  записи и задания прямо в командной строке, код записи сверяет каждый файл данных — всё до первой
  записи; сбой — откат. `run.cmd` в папке задания — только для ручного запуска.
- После прямой записи (без прав администратора) каждый файл сверяется с планом; не совпал — откат.
- Перед записью результат проверяется: вне блока Moon Core и CSP в оболочке не меняется ничего,
  блок один и лежит в `<head>`; иначе запись не делается.

**Необязательные патчи (по умолчанию выключены)**

- Глубокая интеграция: одна строка в бандле воркбенча (`moonCore.deepHooks`) и импорт в
  `out/main.js` (`moonCore.mainProcess`). Бэкап рядом, снятие возвращает файлы байт в байт.
- Стили внутри webview (`moonCore.webviewStyles`): правится только файл-основа webview, у которого
  хэш сходился до Moon Core; файл, уже изменённый другой программой, не трогается. CSS с обратной
  кавычкой, обратным слэшем и `${` не принимается.
- Хук удаления и аварийное восстановление (`moon-core-restore.cmd` / `.sh`) снимают и эти патчи.

**Страховки в окне**

- Страж корня окна: скрыть или сжать `body`, `.monaco-workbench`, область редактора и интерфейс
  самого Moon Core нельзя — ни из окна, ни из профиля, ни из загруженного пакета.
- Стоп-кран (`Ctrl+Alt+Shift+Backspace`) выключает все стили Moon Core без связи с расширением;
  безопасный режим отключает сниппеты, правки и модули во всех окнах.

**Мост «окно — расширение»**

- HTTP только на `127.0.0.1`, случайный токен (48 hex) в каждом запросе, проверка Origin оболочки
  и заголовка Host (защита от сайтов в браузере и DNS-rebinding), только `application/json`,
  лимит частоты и числа потоков. Файл с адресами и токенами доступен только владельцу.

**Код, который исполняется в окне**

- JS-сниппеты берутся только из хранилища расширения, не из папки проекта. Код, изменённый не
  из VS Code (другой программой, синхронизацией), не запустится, пока ты его не одобришь.
- Модули (чужие рантаймы) встраиваются только после согласия; изменённый код модуля — после
  повторного согласия. Файлы модулей проверяются атрибутом `integrity`.
- Команды VS Code из окна (`mc.command`) — каждая новая только после согласия; вопрос один на
  команду, даже если её зовут в цикле. Опасные команды (терминал, установка расширений, git
  push/clean, удаление файлов, `vscode.open`, внутренние `_…`) — модальное подтверждение на каждый
  вызов, «всегда» для них не запоминается; заранее разрешить можно только настройкой
  `moonCore.allowedCommands` (область machine — проект её не задаст).
- Шлюз модулей к API VS Code: настройки с секретами не отдаются (и вырезаются из разделов), файл
  вне проекта, модуля и хранилища открывается только после модального вопроса, уведомления и
  вопросы подписаны именем модуля (модуль не притворится VS Code, спрашивая пароль), один вопрос
  за раз и не больше 10 уведомлений в минуту.
- JS-сниппет, лежащий в папке до первого запуска (или после сброса хранилища), не одобряется молча.
- Профиль проекта (`.vscode/mooncore.json`) в недоверенной папке не предлагается вовсе.
- Селекторы с незакрытыми скобками и кавычками и ключи вроде `__proto__`/`constructor` отбрасываются
  (фаззинг разборщиков в тестах).
- Все решения о разрешениях пишутся в журнал (`Moon Core: Разрешения`); «Отозвать все разрешения»
  сбрасывает их разом.
- Журнал (и его файл `mooncore.log`) вырезает домашнюю папку, токены моста, ключи API, Bearer,
  пароли и логины в URL.
- Импорт вида (файл, Settings Sync, `.vscode/mooncore.json` проекта) проходит те же проверки, что и
  правки из окна: селекторы и CSS-значения без инъекции, настройки только из каталога.
- Сети наружу нет, телеметрии нет.

**Что считать уязвимостью.** Выполнение кода в окне VS Code без согласия пользователя (через
пакет вида, файл проекта, синхронизацию, мост), обход проверки токена или Origin моста, запись
в файлы VS Code вне своего блока, утечка токена моста — об этом стоит сообщить приватно.

**Что не считается.** JS-сниппет или модуль, который ты сам написал или одобрил, может делать
в окне всё, что угодно: это его назначение.
